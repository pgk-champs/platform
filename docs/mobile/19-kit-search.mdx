# Поиск: пауза в наборе и пять состояний выдачи

## Зачем это нужно

«Создайте компонент Поиск» — и рядом, в списке запросов к серверу, отдельной строкой: «Сделан запрос Поиск». Это один пункт критериев с двух сторон: компонент и то, что он вызывает.

Поиск выглядит как поле ввода с иконкой, а внутри — три вещи, которых в обычном поле нет: **пауза перед отправкой**, **пять состояний выдачи** вместо одного списка и **гонка ответов**, из-за которой на экране оказывается выдача по устаревшему запросу.

Весь код собран настоящим компилятором; сообщения об ошибках — его вывод.

## Не на каждый символ

<Figure scheme="kse-debounce" caption="Семь запросов на одно слово против одного" />

Прямое решение — отправлять запрос из `onValueChange` — даёт семь запросов на слово «ноутбук». Это не только трафик: выдача под пальцами мигает и перестраивается на каждую букву, и попасть по нужной строке невозможно.

Правильное поведение: подождать, пока человек **перестанет печатать**.

```kotlin
LaunchedEffect(query) {
    if (query.length < minLength) return@LaunchedEffect
    delay(debounceMillis)
    onSearch(query)
}
```

<SyntaxBreakdown parts={[
  { text: 'LaunchedEffect(query)', label: 'работа, привязанная к значению', note: 'при смене query прошлая корутина ОТМЕНЯЕТСЯ и запускается новая — в этом весь приём' },
  { text: 'delay(debounceMillis)', label: 'пауза', note: 'если за 400 мс человек набрал ещё букву, корутина не доживёт до следующей строки' },
  { text: 'onSearch(query)', label: 'отправка', note: 'до неё дело дойдёт только у той корутины, чей запрос оказался последним' },
  { text: 'query.length < minLength', label: 'порог длины', note: 'по одной букве искать нечего: сервер вернёт полкаталога, а человек всё равно ещё печатает' },
  { text: 'return@LaunchedEffect', label: 'выход из лямбды', note: 'обычный return вышел бы из внешней функции — здесь нужна метка' },
]} />

<Hint type="important">
Пауза здесь бесплатная — не нужно ни таймеров, ни отмены руками. Всю работу делает **ключ** у `LaunchedEffect`: сменился `query` — прошлая корутина отменена вместе со своим `delay`. Именно поэтому приём в Compose выглядит проще, чем в любой другой среде.
</Hint>

Проверим саму отмену на исполняемом примере — без Compose, на чистом Kotlin:

<KotlinPlay code={`import kotlinx.coroutines.*

## Ключ обязателен

```kotlin
@Composable fun P(q: String) { LaunchedEffect { println(q) } }
```

```text
e: Probe.kt:4:32 'fun LaunchedEffect(block: suspend CoroutineScope.() -> Unit): Unit' is deprecated.
LaunchedEffect must provide one or more 'key' parameters that define the identity of the
LaunchedEffect and determine when its previous effect coroutine should be cancelled and a new
effect launched for the new key.
```

Редкий случай, когда сообщение объясняет замысел целиком: ключ определяет, **когда прошлую корутину отменить и запустить новую**. Без ключа неясно, когда работу перезапускать, — поэтому вариант без ключей помечен устаревшим.

А вот попытка подождать прямо в разметке:

```kotlin
@Composable fun P() { delay(400); Text("готово") }
```

```text
e: Probe.kt:5:23 Suspend function 'suspend fun delay(timeMillis: Long): Unit' should be called only from a coroutine or another suspend function.
```

То же сообщение, что в прошлой главе про `hide()`. Разметка не ждёт — ждут корутины.

## Пять состояний, а не список

<Figure scheme="kse-four-states" caption="Под полем поиска пять разных экранов" />

Вторая половина компонента — то, что под полем. Подставить туда просто список значит потерять четыре состояния из пяти:

```kotlin
sealed interface SearchState<out T> {
    data object Idle : SearchState<Nothing>
    data object Loading : SearchState<Nothing>
    data object Empty : SearchState<Nothing>
    data class Found<T>(val items: List<T>) : SearchState<T>
    data class Failed(val message: String) : SearchState<Nothing>
}
```

<SyntaxBreakdown parts={[
  { text: 'sealed interface', label: 'закрытый набор', note: 'наследников ровно пять и все известны компилятору — отсюда проверка полноты в when' },
  { text: 'data object', label: 'состояние без данных', note: 'Idle, Loading и Empty ничего не несут: экземпляр нужен один на всю программу' },
  { text: 'data class Found<T>', label: 'состояние с данными', note: 'единственное, где есть список; в остальных его нет — значит и обратиться к нему нельзя' },
  { text: '<out T>', label: 'ковариантность', note: 'позволяет состоянию без данных объявить тип Nothing и подойти под любой T' },
  { text: 'Failed(val message: String)', label: 'отказ с объяснением', note: 'в критериях это отдельный пункт: ошибку сети и ошибку сервера надо показать, а не проглотить' },
]} />

Компилятор следит, чтобы ни одно состояние не забыли:

```kotlin
sealed interface S { data object A : S; data object B : S }
fun f(s: S): String = when (s) { is S.A -> "a" }
```

```text
e: Probe.kt:3:23 'when' expression must be exhaustive. Add the 'B' branch or an 'else' branch.
```

<Hint type="important">
Здесь стоит **не** писать `else`. Добавили шестое состояние — и компилятор пройдёт по всем местам, где его забыли обработать. С веткой `else` он промолчит, а пользователь увидит пустой экран. Это и есть главная причина брать закрытый набор, а не строку со статусом.
</Hint>

Разметка получается прямым перечислением:

```kotlin
when (state) {
    is SearchState.Idle -> Text("Начните вводить название")
    is SearchState.Loading -> Text("Ищем…")
    is SearchState.Empty -> Text("Ничего не нашлось. Попробуйте другое слово")
    is SearchState.Failed -> Text(state.message)
    is SearchState.Found -> Column { state.items.forEach { item(it) } }
}
```

<Hint type="fact">
Различать «нашлось пусто» и «не смогли спросить» обязательно. Первое — нормальный результат, и человеку надо предложить изменить запрос. Второе — отказ, и там нужна кнопка «Повторить». Экран «ничего не нашлось» при выключенном интернете — классическая претензия на приёмке.
</Hint>

## Гонка ответов

<Figure scheme="kse-race" caption="Ответ на «ноут» приехал позже и затёр выдачу по «ноутбук»" />

Даже с паузой запросов может уйти несколько: человек набрал «ноут», задумался на полсекунды, дописал «бук». Ушло два запроса. Ответы вернутся в произвольном порядке — короткий может обогнать длинный, потому что по нему меньше данных.

Результат: в поле «ноутбук», а на экране выдача по «ноут».

Лечение в Compose встроено и уже написано: `LaunchedEffect(query)` при смене запроса **отменяет** прошлую корутину. Отменённая до `onSearch` не дойдёт — устаревшему ответу просто неоткуда взяться.

<Hint type="tip">
Это одно из мест, где Compose заметно проще предшественников. В обычном коде от гонки защищаются номером запроса: запомнили последний, при ответе сверили и выбросили чужой. Здесь достаточно указать ключ — остальное делает отмена.
</Hint>

## Компонент целиком

```kotlin
@Composable
fun KitSearchField(
    query: String,
    onQueryChange: (String) -> Unit,
    onSearch: (String) -> Unit,
    modifier: Modifier = Modifier,
    label: String = "Поиск",
    placeholder: String = "Название товара",
    minLength: Int = 3,
    debounceMillis: Long = 400,
) {
    LaunchedEffect(query) {
        if (query.length < minLength) return@LaunchedEffect
        delay(debounceMillis)
        onSearch(query)
    }

    KitTextField(
        value = query,
        onValueChange = onQueryChange,
        label = label,
        modifier = modifier,
        placeholder = placeholder,
        imeAction = ImeAction.Search,
        trailing = if (query.isNotEmpty()) {
            { KitButtonGhost(text = "Очистить", onClick = { onQueryChange("") }) }
        } else {
            null
        },
    )
}
```

Три мелочи, которые оценивают:

- **`ImeAction.Search`** — на клавиатуре появляется лупа вместо «Далее»;
- **кнопка очистки** показывается только когда есть что очищать;
- **`onQueryChange` и `onSearch` — разные** параметры: первый срабатывает на каждый символ (поле должно печататься), второй — после паузы.

<Hint type="important">
Разделение этих двух обработчиков — главное в сигнатуре. Попытка обойтись одним приводит либо к запросу на каждый символ, либо к полю, которое не печатается, пока идёт пауза.
</Hint>

## Типичные ошибки

**Ошибка 1. Запрос прямо из `onValueChange`.**

Разобрано: семь запросов на слово.

**Ошибка 2. Пауза руками, через таймер.**

Заводят `Handler`, `Timer` или свою корутину и отменяют её вручную. Работает, но `LaunchedEffect` с ключом делает это надёжнее и без утечек: корутина отменится и при уходе с экрана.

**Ошибка 3. Слишком длинная пауза.**

Секунда и больше воспринимается как «приложение задумалось». Рабочий диапазон — 300–500 мс.

**Ошибка 4. Нет состояния «ищем».**

Между вводом и ответом экран остаётся прежним, и человек набирает снова, решив, что не сработало.

**Ошибка 5. Кнопка очистки всегда видна.**

У пустого поля очищать нечего — крестик на пустом поле выглядит недоделкой.

**Ошибка 6. Поиск по нажатию кнопки и по паузе одновременно.**

Оба пути вызывают `onSearch`, запросы дублируются. Если по макету есть кнопка — либо она, либо пауза.
