# Картинки и загрузка файлов

## Зачем это нужно

Магазин без картинок не бывает. В спецификации задания есть два места, где живут файлы: акции (`news` с полем `newsImage`) и проекты (`project` с полем `image`). Первое — только читать, второе — ещё и **загружать**, причём загрузка описана как `multipart/form-data`, то есть не обычным JSON.

Загрузка файла — отдельный навык. Она не похожа на остальные запросы ни телом, ни аннотациями, и обычный `@Body` здесь не работает. А про то, как показать картинку, у PocketBase своя особенность: в записи лежит **имя файла, а не ссылка**, и адрес нужно собрать самому.

## Что приходит в записи

Запросим акции — это тот самый запрос «Акции и новости» из спецификации:

```
GET /api/collections/news/records
```

```json
{
  "items": [
    {
      "collectionId": "pbc_987692768",
      "collectionName": "news",
      "id": "yzzw0qwd6b6bo0c",
      "newsImage": "banner_y2zhtudxtd.png",
      "title": "Скидка 20% на всё лето"
    }
  ],
  "page": 1,
  "perPage": 30,
  "totalItems": 3,
  "totalPages": 1
}
```

В поле `newsImage` — не адрес, а **имя файла**. Подставить его в загрузчик картинок напрямую нельзя: получится запрос к `banner_y2zhtudxtd.png` относительно текущего адреса, и картинка не найдётся.

<Figure scheme="sf-file-url" caption="Адрес файла собирается из трёх полей записи" />

Правило сборки одно:

```
/api/files/{collectionId}/{id записи}/{имя файла}
```

Все три части лежат в самой записи — специально для этого PocketBase и присылает служебное поле `collectionId`, которое в прошлых главах мы игнорировали.

<KotlinPlay code={`data class NewsDto(
    val id: String,
    val collectionId: String,
    val title: String,
    val newsImage: String = "",
)

const val BASE = "https://style-matule.apis.alspio.com/api"

/** Собирает адрес файла или null, если файла нет. */
fun fileUrl(collectionId: String, recordId: String, name: String, thumb: String? = null): String? {
    if (name.isBlank()) return null
    val suffix = if (thumb == null) "" else "?thumb=\$thumb"
    return "\$BASE/files/\$collectionId/\$recordId/\$name\$suffix"
}

fun main() {
    // то, что реально пришло со стенда
    val news = listOf(
        NewsDto("yzzw0qwd6b6bo0c", "pbc_987692768", "Скидка 20% на всё лето", "banner_y2zhtudxtd.png"),
        NewsDto("33b2r4vv4rbabdr", "pbc_987692768", "Новая коллекция уже в продаже", "banner_o8i7lwqves.png"),
        NewsDto("bez0kartinki0000", "pbc_987692768", "Акция без баннера", ""),
    )

    news.forEach { n ->
        val url = fileUrl(n.collectionId, n.id, n.newsImage)
        println(n.title)
        println("  " + (url ?: "картинки нет — рисуем заглушку"))
    }

    println()
    println("уменьшенная копия:")
    println("  " + fileUrl(news[0].collectionId, news[0].id, news[0].newsImage, thumb = "300x120"))
}`} />

Настоящий вывод:

```
Скидка 20% на всё лето
  https://style-matule.apis.alspio.com/api/files/pbc_987692768/yzzw0qwd6b6bo0c/banner_y2zhtudxtd.png
Новая коллекция уже в продаже
  https://style-matule.apis.alspio.com/api/files/pbc_987692768/33b2r4vv4rbabdr/banner_o8i7lwqves.png
Акция без баннера
  картинки нет — рисуем заглушку
```

<Hint type="important">
Возвращать `null` при пустом имени — не педантизм. Поле файла **вполне может быть пустой строкой**: запись создана, файл не приложен. Если собрать адрес всё равно, получится ссылка, оканчивающаяся на слэш, загрузчик сходит за ней впустую и покажет ошибку. С `null` на этом месте ставится заглушка, и список выглядит целым.
</Hint>

## Показать картинку

Картинки в Compose показывают через `Coil` — библиотеку, которая сама сходит в сеть, закэширует и покажет:

```kotlin
implementation("io.coil-kt:coil-compose:2.7.0")
```

```kotlin
AsyncImage(
    model = fileUrl(news.collectionId, news.id, news.newsImage),
    contentDescription = news.title,
    contentScale = ContentScale.Crop,
    modifier = Modifier.fillMaxWidth().height(160.dp),
)
```

<SyntaxBreakdown parts={[
  { text: 'model = …', label: 'что показать', note: 'принимает строку-адрес, файл, ресурс или null. При null покажется то, что задано в placeholder или ничего' },
  { text: 'contentDescription', label: 'описание для озвучки', note: 'обязательный параметр: экранный диктор прочитает его вслух. Для чисто декоративной картинки пишут null, а не пустую строку' },
  { text: 'contentScale = ContentScale.Crop', label: 'как вписать', note: 'Crop заполняет всю область, обрезая лишнее. Fit вписывает целиком, оставляя поля. Для баннеров обычно Crop' },
  { text: 'Modifier.height(160.dp)', label: 'высота', note: 'без заданного размера карточки в списке будут прыгать, пока картинки грузятся — высоту задают заранее' },
]} />

<Hint type="tip">
Картинки акций и каталога отдаются **без токена** — они публичные. А вот файлы, лежащие в закрытых коллекциях, потребуют заголовок, и тогда `Coil` придётся отдать свой `OkHttpClient` — тот самый, с интерцептором. На сервере задания это не нужно, но знать полезно.
</Hint>

## Уменьшенные копии

У PocketBase есть параметр `?thumb=ШИРИНАxВЫСОТА`, который отдаёт уменьшенную версию. Выглядит как бесплатная экономия трафика — но работает не всегда.

<Figure scheme="sf-thumb" caption="Три запроса одного файла: два размера уменьшены, третий вернул оригинал" />

Проверено на стенде, файл 600×240:

| Запрос | Ответ |
| --- | --- |
| без параметра | 810 байт — оригинал |
| `?thumb=100x100` | 226 байт |
| `?thumb=300x120` | 633 байта |
| `?thumb=50x50` | 810 байт — **оригинал** |

<Hint type="important">
Размеры уменьшенных копий объявляются **в настройках поля коллекции**. Запрос незаявленного размера не даёт ошибки — молча приходит файл целиком. То есть `?thumb=` может «работать» в том смысле, что картинка показывается, и при этом не экономить ни байта.

На чужом сервере узнать список заявленных размеров нельзя. Поэтому надёжнее просить оригинал: `Coil` всё равно масштабирует картинку под размер области и кэширует уже уменьшенную.
</Hint>

## Загрузка: почему не @Body

Создание проекта в спецификации описано как `multipart/form-data`. Это другой формат тела: вместо одного JSON — несколько частей, разделённых строкой-границей, и каждая со своим именем.

<Figure scheme="sf-multipart" caption="Части multipart-запроса и аннотации, которые их описывают" />

Причина проста: JSON — текстовый формат, а картинка двоичная. Засунуть её в JSON можно только закодировав в base64, что раздувает объём на треть и требует раскодирования на сервере. Multipart отправляет байты как есть.

Retrofit описывает такой запрос двумя новыми аннотациями:

```kotlin
@Multipart
@POST("collections/project/records")
suspend fun createProject(
    @Part("title") title: RequestBody,
    @Part("user_id") userId: RequestBody,
    @Part("category") category: RequestBody,
    @Part("description_source") description: RequestBody,
    @Part image: MultipartBody.Part,
): ProjectDto
```

<SyntaxBreakdown parts={[
  { text: '@Multipart', label: 'вид тела', note: 'ставится на метод. Без неё Retrofit откажется собирать запрос и сообщит, что @Part можно использовать только в multipart-методе' },
  { text: '@Part("title") title: RequestBody', label: 'обычное поле', note: 'имя части — в скобках. Обычную строку нельзя передать напрямую: её оборачивают в RequestBody' },
  { text: '@Part image: MultipartBody.Part', label: 'файл', note: 'у файла имя в скобках НЕ ставится — оно уже внутри самой части. Поставить его — частая ошибка: имя уедет дважды' },
  { text: 'description_source', label: 'имя от сервера', note: 'со знаком подчёркивания, как в спецификации. Здесь имена частей задаются строкой, а не через @SerialName' },
]} />

Обернуть строку и файл помогают две функции-расширения из OkHttp:

```kotlin
private fun text(v: String) = v.toRequestBody("text/plain".toMediaType())

val part = MultipartBody.Part.createFormData(
    "image",                 // имя части — то, что ждёт сервер
    "moy-proekt.png",        // имя файла
    bytes.toRequestBody("image/png".toMediaType()),
)
```

<SyntaxBreakdown parts={[
  { text: 'toRequestBody("text/plain".toMediaType())', label: 'строка в тело', note: 'расширение OkHttp: превращает строку или массив байтов в тело части с указанным типом содержимого' },
  { text: 'createFormData(имя, имяФайла, тело)', label: 'часть с файлом', note: 'собирает часть с заголовком Content-Disposition: form-data; name="image"; filename="moy-proekt.png"' },
  { text: '"image/png".toMediaType()', label: 'тип файла', note: 'сервер может проверять его. Указать text/plain для картинки — получить отказ по типу содержимого' },
]} />

Живой прогон загрузки:

```
── загружаем проект с картинкой ──
   размер файла: 1290 байт
   создан 0nluoj149pnafrh, поле image = moy_proekt_8sdyyvnieu.png
   адрес: https://style-matule.apis.alspio.com/api/files/pbc_3202395908/0nluoj149pnafrh/moy_proekt_8sdyyvnieu.png
```

<Hint type="important">
Мы отправили файл с именем `moy-proekt.png`, а в записи оказалось `moy_proekt_8sdyyvnieu.png`. Сервер **переименовывает файл**: заменяет дефисы подчёркиваниями и добавляет случайный суффикс, чтобы два файла с одним именем не затёрли друг друга.

Отсюда правило: адрес картинки строится по имени **из ответа**, а не по тому, что отправляли. Приложение, которое «помнит», как назвало файл, покажет битую ссылку.
</Hint>

## Когда файл не приняли

Поле файла можно ограничить по размеру и типу. На стенде для `image` разрешены `image/png`, `image/jpeg` и `image/webp`, не больше 5 МБ. Попробуем отправить текстовый файл под видом картинки:

```
── чужой файл под видом картинки ──
   код 400 · Failed to create record.
      поле «image»: validation_invalid_mime_type — "vredonos_6d5majznwa.txt" mime type must be one of: image/png, image/jpeg, image/webp.
```

Ошибка приходит в том же виде, что и ошибки формы из главы про регистрацию: код `validation_invalid_mime_type` под ключом `image` в словаре `data`. Разбирается тем же классом `ApiError` — ничего нового писать не нужно.

<Hint type="fact">
Тип содержимого сервер определяет **по самим байтам**, а не по расширению и не по тому, что написано в `Content-Type` части. Переименовать `.txt` в `.png` не поможет: первые байты настоящего PNG — это подпись `89 50 4E 47`, и её отсутствие видно сразу.
</Hint>

Из этого следует, что проверять файл нужно и на устройстве — до отправки:

- **размер**: сравнить с лимитом и сказать «Файл больше 5 МБ» сразу, а не после долгой загрузки по мобильной сети;
- **тип**: у выбранного через системный выбор файла тип можно спросить у `ContentResolver`;
- **сжатие**: снимок с камеры современного телефона легко весит 8–12 МБ, и его почти всегда нужно ужать перед отправкой.

## Откуда берётся файл на устройстве

Выбор картинки из галереи делается системным экраном — без единого разрешения:

```kotlin
val picker = rememberLauncherForActivityResult(
    ActivityResultContracts.PickVisualMedia(),
) { uri -> chosen = uri }

Button(onClick = {
    picker.launch(PickVisualMediaRequest(ActivityResultContracts.PickVisualMedia.ImageOnly))
}) { Text("Выбрать фото") }
```

Приходит `Uri` — не файл и не путь. Чтобы отправить, содержимое надо прочитать:

```kotlin
val bytes = context.contentResolver.openInputStream(uri)?.use { it.readBytes() }
```

<SyntaxBreakdown parts={[
  { text: 'contentResolver.openInputStream(uri)', label: 'открыть поток', note: 'Uri может указывать куда угодно — в галерею, в облако, на другое приложение. Обычного пути к файлу за ним может не быть вовсе' },
  { text: '?.use { … }', label: 'закрыть за собой', note: 'use закрывает поток в любом случае, даже при исключении. Без него поток останется открытым' },
  { text: 'readBytes()', label: 'прочитать целиком', note: 'годится для картинки в несколько мегабайт. Для крупных файлов так делать нельзя — память кончится' },
]} />

<Hint type="tip">
`PickVisualMedia` **не требует разрешения** на чтение хранилища: пользователь сам выбирает файл на системном экране, и приложение получает доступ только к нему. Запрашивать `READ_MEDIA_IMAGES` для выбора картинки — лишнее: диалог разрешения, который можно было не показывать, на оценке работает против вас.
</Hint>

## Типичные ошибки

**1. Имя файла подставили как адрес.** Картинка не грузится, ошибки в коде нет. Адрес собирается из трёх частей.

**2. Не проверили пустую строку.** Запись без файла даёт ссылку, оканчивающуюся слэшем, и в списке появляется битая картинка.

**3. Адрес построили по отправленному имени.** Сервер переименовал файл; брать надо имя из ответа.

**4. Забыли `@Multipart` на методе.** Retrofit скажет, что `@Part` можно применять только в multipart-запросе — при создании клиента, до всякой сети.

**5. У файловой части указали имя в скобках.** Имя уедет дважды, и сервер часть не примет.

**6. Понадеялись на `?thumb=`.** Незаявленный размер молча отдаёт оригинал — экономии нет, а кажется, что есть.

**7. Отправили снимок с камеры как есть.** 10 МБ по мобильной сети — это десятки секунд и почти наверняка отказ по размеру.

**8. Запросили разрешение на галерею.** `PickVisualMedia` работает без него.

## Что засчитывает эксперт

Здесь закрыты три запроса: акции, список проектов и создание проекта с картинкой. Смотрят на это:

- баннеры акций видны на главном экране и не «прыгают» при прокрутке;
- у акции без картинки стоит заглушка, а не пустое место и не значок ошибки;
- картинка выбирается из галереи и уходит на сервер;
- после загрузки она сразу видна в списке — то есть адрес взят из ответа;
- слишком большой или неверный файл отклоняется с понятным сообщением.

<Hint type="fact">
«Не прыгают при прокрутке» — это про заданную высоту у места под картинку. Без неё карточка сначала схлопывается до нуля, потом раздвигается, и список дёргается на каждой загруженной картинке. Замечают это сразу, а чинится одной строкой `Modifier.height(…)`.
</Hint>
