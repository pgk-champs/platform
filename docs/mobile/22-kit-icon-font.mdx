## Зачем это нужно

Последний пункт списка звучит неожиданно: **«Создайте шрифт из представленных иконок»**. Не «добавьте иконки», а именно создайте шрифт.

Задание не выдуманное и не бессмысленное. Иконочный шрифт — старый и до сих пор живой приём: все иконки лежат в одном файле, каждая доступна как обычный символ, красится цветом текста и масштабируется вместе с ним. Никаких отдельных размеров под каждую плотность экрана.

В этой главе мы соберём такой шрифт из четырёх SVG и подключим его в Compose. Всё ниже — настоящий прогон: файлы собраны, проверены и скомпилированы.

## Из SVG в шрифт

<Figure scheme="kif-pipeline" caption="По файлу на иконку — один файл шрифта — четыре символа" />

Исходники — обычные SVG, по файлу на иконку:

```text
svg/
  cart.svg
  heart.svg
  search.svg
  user.svg
```

Сборка одной командой:

```bash
npx fantasticon@4.1.0 svg -o out -n kit_icons -t ttf -g json --font-height 1000 --normalize
```

```text
✔ 4 SVGs found in svg
✔ Generated out/kit_icons.ttf
✔ Generated out/kit_icons.json
Done
```

  { text: '-o out', label: 'куда положить', note: 'папка должна существовать заранее — иначе «Invalid option outputDir: out is not a directory»' },

  { text: '-t ttf', label: 'формат', note: 'для Android нужен именно ttf; woff и eot — это для вебa' },
  { text: '-g json', label: 'карта символов', note: 'файл с соответствием «имя иконки → код»; без него коды придётся выяснять руками' },

Что получилось:

```text
-rw-r--r--  1932 kit_icons.ttf
-rw-r--r--    81 kit_icons.json
```

**Четыре иконки в 1932 байтах** — меньше, чем одна картинка среднего размера.

<Hint type="tip">
Если сборщик ругается `Invalid option outputDir: out is not a directory` — папку вывода надо создать самому: `mkdir -p out`. Сборщик её не создаёт, и сообщение об этом не говорит.
</Hint>

## Проверяем, что собралось

Верить сборщику на слово не стоит — файл шрифта можно открыть и посмотреть:

```python
import fontforge
f = fontforge.open('out/kit_icons.ttf')
print('семейство:', f.familyname, '| глифов:', len(list(f.glyphs())))
for g in f.glyphs():
    if g.unicode > 0:
        print('  U+%04X  %-8s  ширина %d' % (g.unicode, g.glyphname, g.width))
print('единиц на em:', f.em)
```

```text
семейство: kit_icons | глифов: 5
  U+F101  user      ширина 1000
  U+F102  search    ширина 1000
  U+F103  heart     ширина 1000
  U+F104  cart      ширина 1000
единиц на em: 1000
```

Четыре глифа на местах, имена совпадают с именами файлов, ширина у всех одинаковая. Пятый глиф — служебный пустой, он есть в любом шрифте.

<Hint type="fact">
Одинаковая ширина у всех иконок — не случайность и не мелочь. Если одна окажется шире, ряд иконок в панели поедет, а выравнивание по сетке развалится. Именно это делает флаг `--normalize`: приводит все исходники к одной высоте и ширине.
</Hint>

## Почему коды начинаются с F1

<Figure scheme="kif-private-area" caption="Диапазон U+E000…U+F8FF зарезервирован под такие случаи" />

Карта символов, которую выдал сборщик:

```json
{
    "user": 61697,
    "search": 61698,
    "heart": 61699,
    "cart": 61700
}
```

В шестнадцатеричном виде это `U+F101`–`U+F104` — **область для частного использования**. Юникод специально оставил диапазон `U+E000…U+F8FF` пустым: туда никогда не попадёт ни буква, ни знак препинания, ни эмодзи.

Смысл в том, чтобы не пересечься с настоящим текстом. Посади иконку на код буквы `A` — и слово «Cart», написанное этим шрифтом, превратилось бы в набор картинок.

<Hint type="important">
Отсюда же ограничение: текст, набранный иконочным шрифтом, **не читается ничем**. Ни поиском, ни переводчиком, ни экранным диктором — для них там непечатаемый мусор из частной области. Поэтому доступность приходится задавать руками, и об этом — отдельный раздел ниже.
</Hint>

## Подключаем в Compose

Файл кладётся в ресурсы:

```text
ui/src/main/res/font/kit_icons.ttf
```

<Hint type="tip">
Имя файла в `res/font` подчиняется правилам ресурсов Android: только строчные латинские буквы, цифры и подчёркивание. `kit_icons.ttf` годится, `kit-icons.ttf` или `kitIcons.ttf` — нет, сборка упадёт.
</Hint>

Дальше — семейство шрифта и перечисление иконок:

```kotlin
val KitIconFont = FontFamily(Font(R.font.kit_icons))

enum class KitIcon(val glyph: Char) {
    User('\uF101'),
    Search('\uF102'),
    Heart('\uF103'),
    Cart('\uF104'),
}
```

<SyntaxBreakdown parts={[
  { text: 'FontFamily(Font(R.font.kit_icons))', label: 'семейство из ресурса', note: 'R.font.kit_icons появляется автоматически, как только файл лежит в res/font' },
  { text: 'enum class KitIcon', label: 'имена вместо кодов', note: 'в разметке будет KitIcon.Cart, а не \'\\uF104\' — иначе код превращается в магию' },
  { text: "glyph: Char", label: 'иконка это символ', note: 'ровно один символ; строка из двух знаков сюда не поместится, и компилятор это проверит' },
  { text: "'\\uF104'", label: 'запись кода', note: 'обратный слэш, u и четыре шестнадцатеричные цифры — тот самый код из карты символов' },
]} />

И сам компонент:

```kotlin
@Composable
fun KitIconGlyph(
    icon: KitIcon,
    modifier: Modifier = Modifier,
    size: TextUnit = 24.sp,
    tint: Color = LocalContentColor.current,
    description: String? = null,
) {
    Text(
        text = icon.glyph.toString(),
        modifier = modifier.clearAndSetSemantics {
            if (description != null) contentDescription = description
        },
        fontFamily = KitIconFont,
        fontSize = size,
        color = tint,
    )
}
```

<SyntaxBreakdown parts={[
  { text: 'size: TextUnit = 24.sp', label: 'размер в sp', note: 'иконка — это текст, поэтому и размер текстовый; заодно она растёт вместе с системным шрифтом' },
  { text: 'tint: Color = LocalContentColor.current', label: 'цвет по месту', note: 'по умолчанию берёт цвет содержимого от родителя — на тёмной кнопке станет светлой сама' },
  { text: 'clearAndSetSemantics', label: 'стереть и задать', note: 'убирает из дерева доступности сам символ и ставит вместо него описание — или ничего' },
]} />

## Иконка со смыслом и иконка-украшение

<Figure scheme="kif-decoration" caption="Решает не иконка, а то, есть ли рядом текст с тем же смыслом" />

Экранный диктор читает содержимое экрана вслух. Символ из частной области для него — бессмысленный набор байтов, и прочитает он его как мусор. Поэтому у каждой иконки должно быть одно из двух:

**Описание** — когда иконка единственный носитель смысла:

```kotlin
KitIconGlyph(icon = KitIcon.Cart, description = "Корзина")
```

Кнопка с одной корзиной и без подписи без описания становится немой: диктор скажет «кнопка» и всё.

**Явное «ничего»** — когда рядом есть текст с тем же смыслом:

```kotlin
Row {
    KitIconGlyph(icon = KitIcon.Cart)      // description = null
    Text("Корзина")
}
```

Здесь описание только помешало бы: диктор прочитал бы «Корзина. Корзина».

<Hint type="important">
Худший вариант — не задать ничего и не убрать символ из дерева доступности. Тогда диктор попытается прочитать сам глиф. Именно это и делает `clearAndSetSemantics`: убирает символ, а описание ставит только если оно есть.
</Hint>

## Когда иконочный шрифт не подходит

Приём хороший, но не всеобщий. Три случая, когда берут обычные векторные ресурсы:

- **иконка многоцветная** — шрифт одноцветный по устройству, цвет у него один на весь глиф;
- **иконка анимируется** — шрифт не умеет ни морфинга, ни частичной отрисовки;
- **иконок три штуки** — заводить сборку шрифта ради трёх значков дороже, чем положить три файла.

<Hint type="fact">
Отраслевой ход последних лет — обратный: Material перешёл с иконочного шрифта на векторные ресурсы, потому что те поддерживают несколько цветов и переменные начертания. Так что знать приём стоит, а применять — когда он прямо требуется заданием или когда иконок действительно много и все одноцветные.
</Hint>

## Типичные ошибки

**Ошибка 1. Папка вывода не создана.**

```text
Invalid option outputDir: out is not a directory
```

`mkdir -p out` перед сборкой.

**Ошибка 2. Имя файла с дефисом или заглавными.**

`res/font` принимает только строчные, цифры и подчёркивание. Сборка падает на этапе ресурсов.

**Ошибка 3. Коды вписаны в разметку прямо.**

```kotlin
Text(text = "\uF104", fontFamily = KitIconFont)
```

Работает, но через месяц никто не помнит, что такое `F104`. Перечисление с именами — одна строка кода и никакой магии.

**Ошибка 4. Размер в `dp`.**

Иконка перестанет расти вместе с системным шрифтом, а рядом стоящий текст вырастет — значок окажется меньше подписи.

**Ошибка 5. Нет ни описания, ни его отсутствия.**

Диктор читает символ из частной области как мусор.

**Ошибка 6. Иконки разной ширины.**

Без `--normalize` исходники приходят как есть, и ряд значков в панели съезжает.

**Ошибка 7. Шрифт пересобран, а коды не проверены.**

Сборщик раздаёт коды по порядку обхода файлов. Добавили иконку с именем, которое встало в середину списка, — и все последующие коды сдвинулись. Карту символов после каждой пересборки берут заново.
