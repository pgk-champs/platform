# Селект и нижняя шторка: выбор одного из списка

## Зачем это нужно

В критериях два соседних пункта: «Создайте компонент селект» и «Создайте компонент BottomSheet». Это не совпадение — на телефоне они почти всегда одно и то же: селект открывает нижнюю шторку, а шторка показывает варианты.

Заодно здесь впервые в блоке появляются две вещи, которых не было у кнопки и поля: **экспериментальный интерфейс**, который надо разрешить явно, и **асинхронное закрытие** — потому что закрыть шторку значит доиграть анимацию.

Весь код главы собран настоящим компилятором; сообщения об ошибках — его вывод.

## Почему не выпадающий список

<Figure scheme="ks-dropdown-vs-sheet" caption="Выпадающий список оказывается под пальцем, шторка — у большого пальца" />

Привычный по вебу выпадающий список на телефоне работает плохо, и причины механические:

- он раскрывается **вниз от поля**, то есть ровно туда, где сейчас находится рука;
- строки в нём мелкие — попасть пальцем сложнее, чем курсором;
- длинный вариант обрезается: ширина ограничена шириной поля;
- закрыть его можно только нажатием мимо, а «мимо» на телефоне мало.

Нижняя шторка решает всё это разом: она приезжает снизу, к большому пальцу, занимает всю ширину, строки в ней крупные, а закрывается смахиванием вниз.

<Hint type="tip">
Выпадающий список в Compose существует — `DropdownMenu`, и он уместен: в панели инструментов, в меню «ещё» из трёх точек, на планшете. Правило простое: меню действий — выпадающее, выбор значения для формы — шторка.
</Hint>

## Экспериментальный интерфейс

Первое, что произойдёт при попытке использовать шторку:

```kotlin
@Composable fun P() { ModalBottomSheet(onDismissRequest = {}) { Text("шторка") } }
```

```text
e: Probe.kt:5:23 This material API is experimental and is likely to change or to be removed in the future.
```

Это не поломка и не запрет, а предупреждение, поднятое до уровня ошибки: авторы Material 3 оставляют за собой право изменить этот интерфейс. Разрешение даётся явно:

```kotlin
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun KitBottomSheet(…) { … }
```

  { text: 'ExperimentalMaterial3Api::class', label: 'какая именно метка', note: 'у каждой экспериментальной области своя; чужую метку компилятор не примет' },
  { text: 'над функцией', label: 'где ставить', note: 'ставят как можно ближе к месту использования — на функцию, а не на весь файл' },
]} />

<Hint type="important">
Соблазн велик: поставить `@OptIn` один раз на весь файл или, ещё хуже, отключить проверку в настройках сборки. Так делать не стоит именно потому, что предупреждение полезное. Когда библиотека обновится и интерфейс изменится, точечная аннотация покажет ровно те три функции, которые надо посмотреть, а глобальная — ничего.
</Hint>

## Закрыть шторку — это ожидание

Вторая особенность: у шторки есть состояние с анимацией, и закрытие — не мгновенная операция.

```kotlin
val st = rememberModalBottomSheetState()
ModalBottomSheet(onDismissRequest = {}, sheetState = st) { Text("шторка"); st.hide() }
```

```text
e: Probe.kt:10:81 Suspend function 'suspend fun hide(): Unit' should be called only from a coroutine or another suspend function.
```

<Figure scheme="ks-hide-async" caption="Убрать из разметки можно мгновенно; доиграть съезд вниз — нет" />

`hide()` помечена как приостанавливаемая, потому что внутри она ждёт окончания анимации. Вызвать её прямо в разметке нельзя — разметка не умеет ждать. Нужна область корутин:

```kotlin
val state = rememberModalBottomSheetState(skipPartiallyExpanded = true)
val scope = rememberCoroutineScope()

val hide: () -> Unit = {
    scope.launch { state.hide() }.invokeOnCompletion {
        if (!state.isVisible) onDismiss()
    }
}
```

<SyntaxBreakdown parts={[
  { text: 'rememberCoroutineScope()', label: 'откуда запускать', note: 'область, живущая столько же, сколько эта часть разметки; при исчезновении компонента запущенное отменяется' },
  { text: 'scope.launch { state.hide() }', label: 'запустили анимацию', note: 'launch возвращает управление сразу, а анимация играет своим чередом' },
  { text: '.invokeOnCompletion { … }', label: 'после анимации', note: 'здесь и только здесь убираем шторку из разметки — иначе она исчезнет, не доиграв' },
  { text: 'if (!state.isVisible)', label: 'проверка', note: 'анимацию могли прервать: например, человек потянул шторку обратно вверх' },
  { text: 'skipPartiallyExpanded = true', label: 'без промежуточной высоты', note: 'для списка вариантов промежуточное состояние «наполовину» только мешает' },
]} />

<Hint type="fact">
Разница между «убрать» и «закрыть» видна на устройстве сразу. `open = false` заставляет шторку **исчезнуть**, как будто её выключили; правильный путь показывает, как она съезжает вниз. Это ровно тот класс мелочей, из которых складывается впечатление «сделано аккуратно».
</Hint>

## Компонент шторки

```kotlin
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun KitBottomSheet(
    onDismiss: () -> Unit,
    modifier: Modifier = Modifier,
    title: String? = null,
    content: @Composable (hide: () -> Unit) -> Unit,
) {
    val state = rememberModalBottomSheetState(skipPartiallyExpanded = true)
    val scope = rememberCoroutineScope()

    val hide: () -> Unit = {
        scope.launch { state.hide() }.invokeOnCompletion {
            if (!state.isVisible) onDismiss()
        }
    }

    ModalBottomSheet(onDismissRequest = onDismiss, modifier = modifier, sheetState = state) {
        Column(modifier = Modifier.padding(bottom = 24.dp)) {
            if (title != null) {
                Text(
                    text = title,
                    style = MaterialTheme.typography.titleMedium,
                    modifier = Modifier.padding(horizontal = 16.dp, vertical = 12.dp),
                )
            }
            content(hide)
        }
    }
}
```

Обратите внимание на тип слота: `@Composable (hide: () -> Unit) -> Unit`. Это слот **с аргументом** — шторка передаёт внутрь способ закрыть себя. Иначе содержимое не смогло бы закрыть шторку после выбора: состояние анимации живёт внутри компонента.

<Hint type="tip">
Приём «слот получает то, что есть только внутри» встречается постоянно. Так же устроен `Scaffold`, отдающий `innerPadding`, и списки, отдающие индекс элемента. Если содержимому нужно что-то из внутренностей компонента — это передают в слот, а не выносят наружу.
</Hint>

## Сам селект

<Figure scheme="ks-who-owns" caption="Открыта ли шторка — дело компонента; выбранное значение — дело экрана" />

```kotlin
@Composable
fun <T> KitSelect(
    value: T?,
    options: List<T>,
    onSelect: (T) -> Unit,
    label: String,
    modifier: Modifier = Modifier,
    error: String? = null,
    enabled: Boolean = true,
    placeholder: String = "Не выбрано",
    optionText: (T) -> String = { it.toString() },
) {
    var open by remember { mutableStateOf(false) }

    KitTextField(
        value = value?.let(optionText) ?: "",
        onValueChange = {},
        label = label,
        modifier = modifier.clickable(enabled = enabled) { open = true },
        placeholder = placeholder,
        error = error,
        enabled = false,
    )

    if (open) {
        KitBottomSheet(onDismiss = { open = false }, title = label) { hide ->
            options.forEach { option ->
                Text(
                    text = optionText(option),
                    modifier = Modifier
                        .fillMaxWidth()
                        .clickable { onSelect(option); hide() }
                        .padding(horizontal = 16.dp, vertical = 14.dp),
                )
            }
        }
    }
}
```

<SyntaxBreakdown parts={[
  { text: 'fun <T> KitSelect', label: 'обобщённый', note: 'селект не знает, что выбирают: город, размер, категорию — работает с любым типом' },
  { text: 'optionText: (T) -> String', label: 'как показать вариант', note: 'значение по умолчанию toString() годится для строк, для своих типов передают своё' },
  { text: 'value: T?', label: 'может быть не выбрано', note: 'знак вопроса — это состояние «пока ничего», и его надо показать подсказкой' },
  { text: 'enabled = false у поля', label: 'поле только показывает', note: 'вводить руками в селект нельзя; нажатие ловит modifier снаружи' },
  { text: 'modifier.clickable { open = true }', label: 'нажатие на всё поле', note: 'вешается на modifier компонента, а не внутрь: тогда нажимается вся его площадь' },
  { text: 'onSelect(option); hide()', label: 'порядок важен', note: 'сначала сообщаем о выборе, потом закрываем — иначе анимация задержит обновление' },
]} />

<Hint type="important">
Приём с `enabled = false` у поля — обходной, и стоит понимать его цену: отключённое поле выглядит приглушённым. На макете селект обычно нарисован как обычное поле, поэтому цвета для него задают отдельно, через параметры цветов поля, а не полагаются на отключённый вид.
</Hint>

## Типичные ошибки

**Ошибка 1. `@OptIn` на весь файл или отключение проверки в сборке.**

Разобрано выше: при обновлении библиотеки вы потеряете единственную подсказку о том, что именно надо посмотреть.

**Ошибка 2. Закрытие рывком.**

```kotlin
.clickable { onSelect(option); open = false }
```

Работает, но шторка исчезает без анимации. На демонстрации это заметно.

**Ошибка 3. Нажатие повешено на текст внутри поля.**

Тогда нажимается только площадь букв, а не всё поле. `clickable` вешают на `modifier` компонента.

**Ошибка 4. Селект без состояния «не выбрано».**

Если `value` не может быть пустым, при открытии формы там окажется первый вариант — и человек отправит его, не заметив, что ничего не выбирал.

**Ошибка 5. Шторка со списком на сотню строк без прокрутки.**

`Column` не прокручивается. Для длинных списков внутри шторки берут `LazyColumn`, иначе нижние варианты недостижимы.

**Ошибка 6. Обобщённый селект, который печатает объект.**

```kotlin
optionText = { it.toString() }   // Gorod(id=3, name=Самара)
```

Значение по умолчанию годится для строк. Для своих типов передают своё — иначе в шторке окажется отладочный вывод.
