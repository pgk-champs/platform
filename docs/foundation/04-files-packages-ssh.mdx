# Файлы, пакеты, SSH

## Зачем это нужно

На чемпионате тебе выдадут чистую машину с Ubuntu — и почти сразу окажется, что «просто написать код» мало. Скрипт, который ты скачал или написал, откажется запускаться, пока ты не дашь ему право на выполнение. Нужной программы на машине не будет — её придётся установить. А иногда и сама машина будет не перед тобой: сервер стоит в другой комнате (или в другом городе), и подключаться к нему нужно по сети.

Эта глава закрывает все три ситуации. Разберёмся, что такое права доступа и зачем файлу «разрешение быть программой», как одной командой ставить софт из интернета, чем открыть и поправить файл прямо в терминале — и как командой `ssh` оказаться внутри чужого компьютера, не вставая со стула. Это бытовой минимум: без него на Linux не сделать ни одного модуля.

## У файла есть права

В Linux у каждого файла есть права доступа (permission) — отметки, кому и что с ним можно делать: читать (r, read), писать (w, write), выполнять (x, execute). Посмотреть их можно командой `ls -l`:

```bash
ls -l hello.sh
-rw-rw-r-- 1 student student 32 сен  1 10:00 hello.sh
```

Строка `-rw-rw-r--` — это и есть права. Буква на месте — разрешение есть, дефис — нет. Здесь есть r и w, но нигде нет x: файл можно читать и менять, но нельзя запускать. Поэтому попытка выполнить скрипт закончится ошибкой:

```bash
./hello.sh
bash: ./hello.sh: Permission denied
```

Linux не считает файл программой, пока ты явно этого не скажешь, — защита от случайного запуска чего попало. Сказать — одна команда:

```bash
chmod +x hello.sh
./hello.sh
```

`chmod` меняет права, `+x` добавляет право на выполнение — файл становится исполняемым (executable). Это движение — «скачал/написал скрипт → `chmod +x` → запустил» — на соревнованиях делается на автомате.

## Посмотреть и поправить: cat, less, nano

Три команды на каждый день:

- `cat file.txt` — вывалить весь файл в терминал. Идеально для коротких файлов и конфигов.
- `less file.txt` — листать длинный файл постранично: стрелки и PgUp/PgDn — навигация, `/слово` — поиск, `q` — выход. Именно `q`, а не Ctrl+C — это ловит каждого новичка.
- `nano file.txt` — простейший редактор прямо в терминале. Внизу экрана подсказки: `^O` (Ctrl+O) — сохранить, `^X` (Ctrl+X) — выйти. Если файла не было, nano его создаст.

Полноценную IDE это не заменит, но поправить одну строку в конфиге на сервере, где нет никакой графики, — ровно их работа.

## Откуда берутся программы: apt

В Ubuntu программы не скачивают со случайных сайтов по одной. Есть пакетный менеджер (package manager) — программа, которая сама находит нужный софт, скачивает его и ставит вместе со всем, что ему нужно для работы. В Ubuntu он называется `apt`. Единица установки — пакет (package): архив с программой и служебной информацией. Хранятся пакеты в репозитории (repository) — огромном проверенном каталоге софта в интернете.

Рабочая пара команд:

```bash
sudo apt update
sudo apt install htop
```

`apt update` не обновляет программы — он обновляет локальный список того, что вообще есть в репозитории. Поэтому его запускают первым: со свежим списком `apt install` найдёт актуальную версию пакета. А `sudo` впереди означает «выполнить от имени администратора»: установка софта меняет систему целиком, и обычному пользователю такое без спроса не разрешено — система попросит твой пароль (при вводе он не отображается, это нормально).

## Подключиться к чужому компьютеру: SSH

Сервер — это компьютер без экрана и клавиатуры, часто вообще в другом здании. Как им управлять? По сети, через SSH (Secure Shell) — протокол, который открывает терминал удалённой машины прямо в твоём терминале, шифруя всё, что летает между вами. Набираешь команду у себя — выполняется там.

Вернуться к себе — команда `exit`. Машина, к которой подключаются по сети, по-английски называется хост (host) — отсюда и «адрес хоста» в разборе выше.

<details>
<summary>Углубиться</summary>

**Права — это три тройки.** Полная запись `-rw-rw-r--` делится на три группы по три буквы: права владельца файла, права его группы и права всех остальных. Поэтому у `chmod` есть и точная форма: `chmod u+x file` добавляет право на выполнение только владельцу (user), а не всем подряд. Есть и числовая запись вроде `chmod 755` — три цифры кодируют те же три тройки.

**apt update / upgrade / install.** Три разных дела: `update` освежает список пакетов, `upgrade` обновляет уже установленные программы до свежих версий, `install` ставит новые. Всё, что apt делал с системой, записывается в журнал `/var/log/dpkg.log` — можно посмотреть, что и когда ставилось.

**SSH без пароля.** В реальной работе по паролю почти не ходят: генерируют пару ключей (`ssh-keygen`), кладут публичный ключ на сервер — и вход происходит без ввода пароля, а подобрать такой «пароль» невозможно. На чемпионате достаточно парольного входа, но слова «ssh-ключ» пугать не должны.

Дальше по теме:
- [Ubuntu Server — Package management](https://ubuntu.com/server/docs/how-to/software/package-management/) — официальная документация apt: update, upgrade, install, remove
- [man chmod](https://manpages.ubuntu.com/manpages/noble/en/man1/chmod.1.html) — страница руководства chmod: символьная и числовая записи прав
- [OpenSSH manual pages](https://www.openssh.org/manual.html) — документация ssh, ssh-keygen и всей семьи инструментов OpenSSH

## Челлендж ⭐

Пакет `tree` рисует дерево каталогов прямо в терминале — наглядная замена `ls`, когда папок много. На свежей Ubuntu его нет.

Твоя задача, всё — в терминале:

1. Установи пакет `tree` через apt (не забудь про свежий список пакетов).
2. Докажи, что установка удалась: выведи версию программы.
3. Запусти `tree` в своей домашней папке и посмотри на результат.

Подсказка: у большинства программ версию выдаёт флаг `--version`.

<details>
<summary>Решение (сначала попробуй сам)</summary>

```bash
sudo apt update
sudo apt install tree
tree --version
tree ~
```

`apt update` освежает список пакетов, `apt install tree` ставит пакет, `tree --version` печатает версию (значит, программа реально установлена и находится системой), `tree ~` рисует дерево домашней папки.

</details>

- Читать строку прав из `ls -l` и объяснять, почему `./script.sh` может ответить «Permission denied».
- Делать файл исполняемым через `chmod +x` и запускать его.
- Выбирать между `cat`, `less` и `nano` под задачу и выходить из less и nano, не перезапуская терминал.
- Объяснять, зачем перед `apt install` запускают `sudo apt update` и что делает `sudo`.
- Читать и составлять команду подключения вида `ssh user@host -p port` и объяснять каждую её часть.
