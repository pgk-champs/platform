## Зачем это нужно

В Ethereum данные контракта живут в его собственных полях. В Fabric — в общем хранилище «ключ — значение», доступном через объект контекста. В Waves сделано третье: **у каждого аккаунта есть свой словарь**, и писать в него можно вообще без всякого кода, обычной транзакцией.

Это неожиданно удобно. Прежде чем писать смарт-контракт, можно уже вести журнал: записывать оценки, статусы поставок, показания счётчиков. И это же хранилище потом читает и меняет dApp — то есть данные и код разведены.

Эта глава — про этот словарь: что в нём можно хранить, сколько это стоит и где границы. Все числа ниже сняты на локальном узле Waves 1.6.4.

## Словарь аккаунта

<Figure scheme="wd-storage" caption="Свой словарь у каждого аккаунта; писать можно только в свой, читать — любой" />

Пишем три значения:

```js
const { data } = require('@waves/waves-transactions');

const tx = data({ data: [
  { key: 'gruppa', type: 'string',  value: 'IS-21' },
  { key: 'ball',   type: 'integer', value: 5 },
  { key: 'dopusk', type: 'boolean', value: true },
], chainId: 'R' }, seed);
```

```text
тип: 12 | комиссия: 100000
в блоке: 28
```

<SyntaxBreakdown parts={[
  { text: 'data({ data: [...] })', label: 'транзакция типа 12', note: 'внутреннее поле тоже называется data — это список записей, а не одна' },
  { text: 'key: \'gruppa\'', label: 'ключ', note: 'произвольная строка до 400 знаков; адрес получателя нигде не указывают' },
  { text: 'type: \'string\'', label: 'тип значения', note: 'один из четырёх: integer, boolean, string, binary' },
  { text: 'value: 5', label: 'значение', note: 'целое; дробных чисел в состоянии не бывает вовсе' },
]} />

Читаем:

```bash
curl http://127.0.0.1:6869/addresses/data/3M5HPFG1r9q79uxff6rm1Z3UFZcXXXHX32p
```

```text
[{"key":"ball","type":"integer","value":5},
 {"key":"dopusk","type":"boolean","value":true},
 {"key":"gruppa","type":"string","value":"IS-21"}]
```

Порядок — алфавитный по ключу, а не тот, в котором записывали.

<Hint type="important">
В транзакции данных **нет получателя**. Запись всегда идёт в словарь того, кто подписал. Это главное правило: чужой словарь не изменит никто, включая владельца узла. А вот читать может кто угодно — состояние публично внутри сети.
</Hint>

## Четыре типа значений и удаление

<Figure scheme="wd-value-types" caption="Четыре типа плюс особый случай: значение null удаляет ключ" />

| Тип | Пример | Что это |
| --- | --- | --- |
| `integer` | `5` | целое со знаком |
| `boolean` | `true` | да или нет |
| `string` | `"IS-21"` | текст в UTF-8 |
| `binary` | `base64:AbCd…` | произвольные байты |

Дробных чисел нет. Цену в рублях и копейках хранят целым числом копеек — ровно так же, как суммы в самой сети.

Удаление — запись со значением `null` и **без типа**:

```js
const tx = data({ data: [{ key: 'ball', value: null }], chainId: 'R' }, seed);
```

```text
состояние до:    [{"key":"ball",...},{"key":"dopusk",...},{"key":"gruppa",...}]
состояние после: [{"key":"dopusk","type":"boolean","value":true},{"key":"gruppa","type":"string","value":"IS-21"}]
```

<Hint type="fact">
Удаление убирает ключ из **текущего** состояния, но не из истории: транзакция, которая его записывала, никуда из цепочки не делась. Блокчейн остаётся блокчейном — стереть прошлое нельзя, можно только перестать считать его текущим.
</Hint>

## Сколько это стоит и где границы

<Figure scheme="wd-limits" caption="Проверено на живом узле: где именно проходят границы" />

Цена растёт по килобайтам:

```text
значение    10 байт → комиссия 100000
значение  1000 байт → комиссия 100000
значение  1100 байт → комиссия 200000
значение  2100 байт → комиссия 300000
значение  3100 байт → комиссия 400000
```

То есть **0,001 WAVES за каждый начатый килобайт**. Первый килобайт стоит столько же, сколько десять байт, а вот 1100 байт — уже вдвое дороже.

Границы (проверено перебором):

```text
ключ 400 знаков  → код 200
ключ 401 знак    → код 400 | Too big sequence requested
значение 32 767 байт → код 200
значение 32 768 байт → код 400 | Too big sequence requested
```

<Hint type="tip">
Сообщение `Too big sequence requested` одно на оба случая — и на длинный ключ, и на большое значение. Что именно велико, узел не уточняет, так что проверять придётся самому.
</Hint>

Одной транзакцией можно записать много ключей сразу — сто штук прошли без вопросов. Комиссию при этом надо ставить по размеру:

```text
100 ключей с комиссией 100000 → State check failed. Reason: Fee for DataTransaction
                                (100000 in WAVES) does not exceed minimal value of 200000 WAVES.
100 ключей с комиссией 300000 → код 200
```

## Как читать состояние

**Весь словарь целиком:**

```bash
curl .../addresses/data/<адрес>
```

**Один ключ:**

```bash
curl .../addresses/data/<адрес>/n7
```

```text
{"key":"n7","type":"integer","value":7}
```

**Несуществующий ключ:**

```text
код: 404 | {"error":304,"message":"no data for this key"}
```

**Ключи по образцу** — то, что заменяет вложенные структуры:

```bash
curl '.../addresses/data/<адрес>?matches=n1%5B0-9%5D'
```

```text
найдено: 10
[{"key":"n10","type":"integer","value":10},{"key":"n11",…},{"key":"n12",…}]
```

<SyntaxBreakdown parts={[
  { text: '?matches=', label: 'фильтр по ключу', note: 'обычное регулярное выражение; в адресе строки его надо закодировать' },
  { text: 'n1[0-9]', label: 'образец', note: 'совпало десять ключей: n10…n19' },
  { text: '%5B0-9%5D', label: 'то же в URL', note: 'квадратные скобки в адресе кодируются — иначе узел получит не то, что вы написали' },
]} />

<Hint type="important">
Вложенных структур в состоянии нет. Вместо `студенты[z-1].оценки` пишут **составной ключ**: `z_z-1_ball`. А потом достают все ключи студента одним запросом по образцу. Этот приём встречается в каждом втором dApp.
</Hint>

## Типичные ошибки

**Ошибка 1. Искать поле получателя.**

Его нет. Записать в чужой словарь нельзя никаким способом — это не ограничение библиотеки, а правило сети.

**Ошибка 2. Ставить комиссию по умолчанию на большую запись.**

```text
State check failed. Reason: Fee for DataTransaction (100000 in WAVES)
does not exceed minimal value of 200000 WAVES.
```

Библиотека считает комиссию по размеру сама, если её не задавать вручную. Задали — считайте сами.

**Ошибка 3. Хранить дробное число.**

Тип `integer` не примет `1.5`. Хранить надо копейки или тысячные доли, а запятую ставить при показе.

**Ошибка 4. Забыть закодировать образец в адресе.**

`?matches=n1[0-9]` без кодирования доедет до узла искажённым, и ответ будет пустым — без всякой ошибки.

**Ошибка 5. Складывать в состояние файлы.**

Тип `binary` есть, но 32 767 байт — это потолок, и каждый килобайт платный. Файлы кладут в обычное хранилище, а в состояние — только их хеш.

## Что должен уметь после главы

- записать несколько значений в состояние своего аккаунта и прочитать их;
- назвать четыре типа значений и объяснить, почему нет дробных чисел;
- удалить ключ и объяснить, что при этом происходит с историей;
- посчитать комиссию по размеру записи;
- назвать границы ключа и значения и узнать соответствующее сообщение;
- заменить вложенную структуру составным ключом и выборкой по образцу.
