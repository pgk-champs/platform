# Платежи в dApp: банк вкладов на RIDE

## Зачем это нужно

Зачётка из прошлой главы данными и ограничилась. Настоящее приложение обычно работает с деньгами: принимает, хранит, возвращает. И вот тут появляется вопрос, который в Solidity решается словом `payable`, а здесь — иначе и удобнее.

В Waves деньги **прикладывают к вызову**. Не переводят отдельной транзакцией, не разрешают списание заранее — кладут прямо в ту же транзакцию, которая зовёт функцию. К моменту, когда функция начала считать, деньги уже на счёте приложения.

Эта глава — про этот механизм и про четыре проверки, без которых приложение теряет деньги. Написан и прогнан настоящий банк вкладов на локальном узле Waves 1.6.4.

## Что приложено к вызову

<Figure scheme="wpm-payments" caption="Платёж едет в той же транзакции, что и вызов" />

Со стороны клиента:

```js
const tx = invokeScript({
  dApp: bank,
  call: { function: 'polozhit', args: [] },
  payment: [{ amount: 300000000, assetId: null }],
  chainId: 'R',
}, seed);
```

<SyntaxBreakdown parts={[
  { text: 'payment: [...]', label: 'что прикладываем', note: 'список: в одном вызове можно приложить до двух платежей' },
  { text: 'amount: 300000000', label: 'сумма в «копейках»', note: 'это 3 WAVES' },
  { text: 'assetId: null', label: 'какая монета', note: 'null означает WAVES; для токена ставят его идентификатор' },
]} />

Со стороны скрипта:

```ride
@Callable(i)
func polozhit() = {
  let pay = i.payments[0]
  if (pay.assetId != unit) then throw("Prinimayu tolko WAVES")
  else {
    let k = kluch(i.caller)
    let bylo = match getInteger(this, k) { case n: Int => n case _ => 0 }
    [ IntegerEntry(k, bylo + pay.amount) ]
  }
}
```

<SyntaxBreakdown parts={[
  { text: 'i.payments[0]', label: 'первый платёж', note: 'список может быть и пустым — обращение к [0] тогда уронит скрипт' },
  { text: 'pay.assetId != unit', label: 'проверка монеты', note: 'в RIDE «ничего» называется unit; у платежа в WAVES assetId именно такой' },
  { text: 'pay.amount', label: 'сумма', note: 'целое в «копейках», ровно то, что приложил вызвавший' },
  { text: 'kluch(i.caller)', label: 'составной ключ', note: 'вклад каждого лежит под своим ключом: "vklad_" + адрес' },
  { text: 'bylo + pay.amount', label: 'прибавляем к прежнему', note: 'состояние приложения ведёт учёт; сами деньги уже на его счёте' },
]} />

<Hint type="important">
Деньги приходят на счёт приложения **до** выполнения функции. Если функция упадёт, транзакция целиком не применится, и платёж тоже не состоится. Но пока она работает, на счёте уже лежит и старое, и новое — это важно помнить при расчётах баланса.
</Hint>

## Выдача: `ScriptTransfer`

```ride
@Callable(i)
func zabrat(skolko: Int) = {
  let k = kluch(i.caller)
  let est = match getInteger(this, k) { case n: Int => n case _ => 0 }
  if (skolko > est) then throw("Na schete tolko " + est.toString())
  else [ IntegerEntry(k, est - skolko), ScriptTransfer(i.caller, skolko, unit) ]
}
```

<SyntaxBreakdown parts={[
  { text: 'ScriptTransfer(i.caller, skolko, unit)', label: 'перевод со счёта dApp', note: 'три аргумента: кому, сколько, в какой монете; unit — это WAVES' },
  { text: 'IntegerEntry(k, est - skolko)', label: 'уменьшить учёт', note: 'вместе с переводом, одним списком: либо оба, либо ни одного' },
  { text: 'est.toString()', label: 'число в строку', note: 'в сообщении об ошибке видно, сколько на самом деле есть' },
]} />

Живой прогон:

```text
### кладём 3 WAVES
изменения: [{"key":"vklad_3M57BFmz…","type":"integer","value":300000000}]
```

</Hint>

## Четыре обязательные проверки

<Figure scheme="wpm-checks" caption="Сеть проверяет только балансы; смысл операции проверяет ваш код" />

**Платёж вообще есть?**

```ride
if (i.payments.size() == 0) then throw("Nuzhen platezh") else …
```

Без этого обращение к `i.payments[0]` уронит скрипт — не с вашим сообщением, а с невнятным сбоем.

**Та ли монета?** Самая частая пропущенная проверка. Прикладываем токен вместо WAVES:

```text
код: 400
{"error":112,"message":"State check failed. Reason: Attempt to transfer unavailable funds:
Transaction application leads to negative asset '3fyDK2Da…' balance …"}
```

В этом прогоне отказала сама сеть — токенов на счёте не было. Но если бы они были, платёж прошёл бы, и приложение записало бы вклад в WAVES за приложенный токен. Проверка `pay.assetId != unit` стоит одну строку и спасает от этого.

**Сумма разумна?** Ноль и отрицательные значения отсекает сеть, но логика может требовать минимума — тогда проверять надо самому.

**Хватает ли на счёте?**

```text
код: 400
{"error":306,"message":"Error while executing dApp: Na schete tolko 200000000"}
```

Без этой проверки приложение выдало бы чужие деньги: на его счёте лежат вклады всех.

<Hint type="important">
Учёт в состоянии и деньги на счёте — **разные вещи**. Сеть следит только за вторым. Если в коде ошибка, сумма вкладов перестанет сходиться с балансом, и узнаете вы об этом в тот момент, когда кому-то не хватит на выдачу.
</Hint>

## Возврат значения из функции

Вызываемая функция может вернуть не только список действий, но и значение:

```ride
@Callable(i)
func skolko() = {
  let k = kluch(i.caller)
  let est = match getInteger(this, k) { case n: Int => n case _ => 0 }
  ([], est)
}
```

Пара: пустой список действий и число. Такой вызов ничего не меняет, но всё равно остаётся транзакцией — за него платят комиссию и он попадает в блок.

<Hint type="tip">
Для чтения это плохой способ: платить 0,005 WAVES за то, что можно бесплатно прочитать запросом `/addresses/data/<адрес>/<ключ>`, незачем. Возврат значения нужен для другого — чтобы **один dApp мог позвать другой** и получить ответ.
</Hint>

## Сложность по функциям

Узел показывает стоимость каждой функции отдельно:

```bash
curl .../addresses/scriptInfo/<адрес банка>
```

```text
"callableComplexities":{"polozhit":20,"zabrat":22,"skolko":14}
```

Двадцать с небольшим — очень мало. Для сравнения, один `sigVerify` стоит 182. Работа с состоянием и деньгами почти ничего не стоит; дорого обходится криптография.

## Типичные ошибки

**Ошибка 1. Не проверить монету.**

Разобрана выше. Одна строка кода, а без неё приложение принимает что угодно.

**Ошибка 2. Считать баланс приложения вместо учёта.**

```ride
let est = wavesBalance(this).available     // это ВСЕ вклады, а не вклад вызвавшего
```

На счёте приложения лежат деньги всех. Учёт ведут в состоянии, под ключом на каждого.

**Ошибка 3. Уменьшить учёт, но забыть перевод.**

Или наоборот. Оба действия — в одном списке, иначе состояние и деньги разойдутся.

**Ошибка 4. Переводить `i.caller` вместо `i.originCaller`, не понимая разницы.**

Когда один dApp зовёт другой, `i.caller` — это позвавший dApp, а `i.originCaller` — человек, начавший всю цепочку. Для банка вкладов правильный вариант — `i.caller`: деньги вернутся туда, откуда пришли.

**Ошибка 5. Читать состояние платным вызовом.**

Комиссия 0,005 WAVES за то, что читается бесплатно обычным запросом к узлу.

- отличить платёж в WAVES от платежа токеном;
