# Как предложить правку

Нашли опечатку, ошибку в примере или непонятное объяснение? Любую страницу
платформы можно поправить — как в Википедии. Есть два пути: совсем простой
(форма) и чуть посложнее (правка текста прямо на GitHub). Для обоих нужен
только аккаунт GitHub — если его ещё нет, начните со страницы
«Регистрация на GitHub с нуля» на платформе.

## Путь 1. Форма «Предложить правку» (самый простой)

Подходит, когда хочется просто сообщить о проблеме, а исправлять пусть будут
наставники.

1. Откройте главу, где нашли проблему.
2. Пролистайте вниз — под текстом есть кнопка с карандашом **«Предложить правку»**.
3. Откроется форма на GitHub. Поле «Глава» уже заполнено автоматически.
4. Напишите **«Что не так»** — своими словами, без терминов.
5. Если есть идея, как лучше, — заполните **«Как лучше»** (необязательно).
6. Нажмите зелёную кнопку **Submit new issue** («Отправить»).

Готово. Наставник увидит заявку (метка «правка»), поправит текст и закроет её —
вам придёт уведомление на почту.

## Путь 2. «Редактировать страницу» → Pull Request

Подходит, когда вы готовы исправить текст сами. Звучит страшно, на деле —
четыре клика, GitHub всё делает за вас.

1. Внизу главы нажмите **«Редактировать страницу»**.
2. GitHub откроет исходник главы. Если появится сообщение про «fork» —
   нажмите зелёную кнопку **Fork this repository**: GitHub создаст вашу личную
   копию (это нормально и ничего не ломает).
3. Исправьте текст прямо в редакторе в браузере. Форматирование — обычный
   Markdown: `**жирный**`, `*курсив*`, списки через дефис.
4. Нажмите **Commit changes** и в описании коротко напишите, что поменяли
   (например: «исправил опечатку в команде git»).
5. GitHub предложит создать **Pull Request** — соглашайтесь (**Create pull request**).

Дальше правку посмотрит наставник: примет её («merge») или напишет вам
комментарий, если что-то нужно уточнить. После принятия изменение появится
на сайте автоматически.

## Что можно править

- Опечатки, грамматику, пунктуацию.
- Ошибки в примерах кода и командах.
- Непонятные формулировки — переписать понятнее.
- Битые ссылки.

Крупные изменения (новая глава, переделка раздела) лучше сначала обсудить:
откройте issue через форму из пути 1 и опишите идею.

## Комментарии к главам

Под каждой главой есть блок комментариев (вход через GitHub). Если не уверены,
что нашли ошибку, — просто спросите там: обсудим.
