## 1. Что это

Учебная платформа для подготовки к чемпионату «Профессионалы» — треки **Мобилка** (Kotlin/Compose) и **Блокчейн** (TypeScript/Waves), общий **Фундамент** и **Отдельные темы**.

- Docusaurus 3.10.2, TypeScript, статика.
- Единственный живой адрес — **https://edu.alspio.com**. GitHub Pages выключен.
- Пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) → сборка с гейтами → rsync на VPS. Отдельной команды деплоя нет: **выложить = запушить в main**.
- Глав на 13.09.2026 — **137**: фундамент 10, мобилка 46, блокчейн 72, отдельные темы 9. Экзаменов по блокам (`BlockExam`) — 12.

- **Kotlin-факты, снятые вживую 13.09** (пригодятся в других главах): `readLine()` помечена устаревшей **начиная с 2.1.0** (на 2.0.21 предупреждения нет — проверено по пяти версиям); нажатый Enter даёт `""`, а не `null`; `readln()` после конца ввода бросает `kotlin.io.ReadAfterEOFException: EOF has already been reached`; `" 42 ".toIntOrNull()` → **null**, а `toDoubleOrNull()` → 42.0; `"3,5"` не читается ни тем, ни другим; `"%.2f".format` даёт **1234,50** при локали ru_RU и **1234.50** при en_US — локаль плейграунда `en_US`, локальной машины `ru_RU`, так что проверка формата в плейграунде НЕ доказывает поведение на устройстве.
- **Плейграунд не даёт stdin:** `readlnOrNull()` там всегда `null`. Примеры с вводом делаются исполнимыми через подмену чтения заготовленным списком строк. ## 3. Правила работы

- **Решай сам** всё, что касается «как» — структура главы, формулировки, вёрстка схем, выбор примеров.
- **Спрашивай** про «что» — какую тему писать, какой трек двигать, что переделывать. Это доска, а не догадки.
- Не спрашивай разрешения на перезапуск локальных сервисов и на коммит рутинной работы — это шум.
- Дизайн: показывай **варианты**, а не вопросы «как сделать».

## 5. Контракт «добавить главу»

Глава подключается к сайдбару сама, и **четыре места надо тронуть руками**. Трек, номер и заголовок обложки, а также знаменатели прогресса выводятся из файла — дублировать их больше негде и незачем (было шесть мест, половина — переписывание одного и того же; убрано 15.09.2026).

1. **`docs/<трек>/NN-slug.mdx`** — фронтматтер обязателен целиком:
   ```yaml
   title: '…'
   audience: 'все' | 'мобилка' | 'блокчейн'   # другие значения → kmap падает
   level: 'база' | 'углубление' | 'челлендж'
   order: N
   ```
2. **`src/components/figures/<модуль>.tsx`** — 2–5 схем + рядом `<модуль>.test.tsx`.
3. **`Figure.tsx`** — импорт модуля **и** спред в `SCHEMES` (две строки).
4. **`Figure.test.tsx`** — импорт **и** `...Object.keys(<модуль>Schemes)` (две строки). Тест сверяет `SCHEME_IDS.length === all.length`, поэтому забыть нельзя.
5. **`src/data/chapter-videos.json`** — ровно 4–5 видео, и **3–7 вопросов** в `DAILY_BANK` (`DailyChallenge.tsx`). Глава без вопросов роняет vitest: `CHAPTER_META` строится из карты знаний.

Арт обложки в `ChapterCover.tsx` (`ART`) — по желанию: без своей записи подставится арт трека.

**Простая страница — не глава.** Памятке, объявлению или разбору задания хватает `kind: 'page'` во фронтматтере: ни обложки, ни экзамена, ни схем, ни видео, ни вопросов дня. Стражи глав её намеренно не видят, в `knowledge-map.json` она не попадает (иначе ждали бы нулевой главой в зале и в дашборде — на этом упала сборка 15.09.2026), а лежит в `pages.json`. В маршруте показывается отдельным блоком «Страницы» — без галочки и статуса.

**Страницу заводят прямо на сайте** — `/edit`, роль автора выдаёт наставник. Правка идёт коммитом через GitHub Contents API (`CONTENT_TOKEN` в `/opt/edu-alspio/.env`), путь проверяется регуляркой `SAFE_DOC_PATH` — она под отдельным тестом `server/content-path.test.mjs`, ослаблять нельзя: тем же запросом можно было бы переписать код сервера или workflow деплоя.

**Главу из редактора завести НЕЛЬЗЯ, и выбор типа там убран** (15.09.2026). Причина: схемы, видео и вопросы дня лежат вне `docs/`, куда редактору писать запрещено. Пока выбор был, «Глава» вела к коммиту, который валит сборку — а сборка это и есть публикация, то есть падение блокировало выкладку всего сайта.

**Способов добавить и править — ровно три, пересечений нет:**

| Что | Куда | Кто |
| --- | --- | --- |
| правка текста страницы | `/edit`, либо «Предложить правку» (issue) под страницей | автор / любой |
| новая страница | `/edit` → «+ Новая страница» | автор |
| видео, ссылка, пресет в каталог | `/community` (issue) | любой |

Ссылка «Редактировать страницу» (`editUrl` Docusaurus) **убрана** — она вела в веб-редактор GitHub и была четвёртым путём, противоречащим обещанию «ни программы, ни git». Справочник для людей один: `docs/advanced/kak-dobavit-stranicu.mdx` («Как добавить материал»), на него ведут навбар, индекс раздела и экран «Нет доступа» в редакторе.

**Перенумеровать главы внутри трека безопасно** — числовой префикс в URL не попадает, а номер обложки читается из имени файла. Ничего править вручную не нужно. Переименовывать файлы **обратным порядком** (13→ сначала, потом 12), иначе `mv` попадёт в существующее имя.

**`chapterId` менять нельзя.** К нему привязаны прогресс, избранное, XP, словарь, вопросы дня и дашборд наставника — а не к пути. Переезд главы между треками дёшев, смена `chapterId` — нет.

## 6. Из чего состоит глава (канон v2+)

Обязательный минимум, его проверяют стражи:

- `<ChapterCover chapterId="…" />` сразу после фронтматтера;
- `<ChapterProgress chapterId="…" />` — знаменатели считает карта знаний, руками их не пишут;
- 2–5 `<Figure>`, ровно один `<ChapterExam>`, 4–5 видео;
- `<SectionAnchor>` в **конце** каждой секции (метка «секция прочитана» стоит после текста, не до);
- `<Hint type="tip" | "important" | "fact">` — **других значений нет**, невалидное падает только на `build`;
- `<Block kind="trainer" | "quiz" | "breakdown" | "vocab" | "cheatsheet" | "fact">`.

Содержательные требования калибровки Олега: посимвольный `SyntaxBreakdown` на каждую новую конструкцию, каждый символ объяснён при первом появлении, построчный разбор примеров, секция «Типичные ошибки» с **настоящими** текстами компилятора, `SelfCheck` после каждой крупной секции, объём не режется ради краткости, каждый пример исполняемый (`KotlinPlay`).

## 7. Инварианты, которые НЕ ловит ни один тест

Это самое ценное в файле. Всё остальное поймает CI.

**Каталог сообщества переехал на сервер целиком** (проверено 21.09.2026: `/api/community` отдаёт 24 материала с серверными id, `COMMUNITY_JSON_URL` в коде больше нет). Статический `community.json` в репозитории `pgk-champs/community` и бот по issue выведены из обращения: ссылка на шаблон снята, гайд `/community-guide` и тренажёр формы удалены. Единственный источник витрины — `/api/community`.

Подвал главы (`ChapterSources`) уже читает сервер: раньше он читал только статический файл, и одобренный материал у главы не появлялся никогда.

**Ручной отметки «пройдено» больше нет нигде** (15.09.2026). Прогресс считается по делам: `src/lib/chapterFill.ts`, формула — `(секции + идеальные проверки + тренажёры) / (всего секций + проверок + тренажёров)`. Проверка с ошибкой НЕ засчитывается; тренажёр засчитывается фактом прохождения — общей шкалы «верно» у сорока шести механик нет. **Тренажёры вошли в счёт 17.09.2026**: до этого в шапке главы висело отдельное «Тренажёры 0/6», а сосуд наливался до крышки, ни одного не спросив. У всех, кто учился раньше, сосуды после этого стали ниже, а сертификат пришлось добирать — решение принято сознательно, пока не пришли первокурсники. Ключ `pgk-progress` удалён; тема сосудов лежит в `prefs` того же store.

Кто это читает: сосуды Маршрута, карточка «Продолжить», сертификат и **тренажёр слов** — он берёт словарь из глав, наполненных до крышки. Менять формулу — значит двигать все четыре разом: при правке 17.09.2026 упали ровно `ContinueCard.test.tsx` и `WordsTrainer.test.tsx`, и это правильный список.

**Шапка главы и сосуд Маршрута считают ОДНО И ТО ЖЕ и одним кодом** (21.09.2026). Шапка считала квизы по числу ключей в `progress.quizzes[chapterId]`, а `chapterFill` — только целиком верные. Студент, ответивший всё неверно, видел «Квизы 3/3» и считал проверку сданной, а сосуд при этом стоял пустой. Числа теперь приходят из `partsOf()` — там же, где их берёт сосуд. Заодно перестала врать плашка результата: она печатала «Пройдено: N из M» по числу верных НА ЭКРАНЕ, то есть «Пройдено: 0 из 3» ответившему всё мимо и «Пройдено: 2 из 2» исправившему ошибку, хотя в зачёт ушло 1 из 2. Теперь «Проверка пройдена» — только когда всё взято с первой попытки. Страж в `ChapterProgress.test.tsx` сверяет закрашенные клетки с `partsOf`; прежний тест закреплял как раз сломанное поведение.

**`ChapterProgress` — арифметику больше не пишут руками, и это единственный инвариант отсюда, который удалось убить.** Знаменатели считает `knowledge-map.mjs` прямо по тексту главы: секции — по `<SectionAnchor>`, квизы — по `<SelfCheck>` **плюс один за `<ChapterExam>`** (экзамен пишет в тот же счётчик через `markQuizDone(chapterId, 'exam', …)`), тренажёры — по `trainerId=` (это НЕ то же, что блоки `kind="trainer"`: тренажёр без `trainerId` прогресс не пишет и в знаменатель не идёт — так в `linux-terminal`, где блоков семь, а тренажёров шесть).

Пока числа писали руками, компонент делал `Math.min` и молчал: завысил — полоса никогда не дойдёт до 100 %, занизил — лишние прохождения теряются. Так 41 глава из 52 оказалась с заниженным знаменателем (правило про экзамен было записано здесь неверно, исправлено 05.09.2026), а в `kotlin-null` заявили 4 квиза при трёх написанных. Пропсы `totalSections` / `totalQuizzes` / `totalTrainers` у компонента остались — они перекрывают расчёт, и нужны только если посчитанное по тексту заведомо врёт.

**Шкала уровней калибруется под объём платформы, а не наоборот** (18.09.2026). Прежняя кривая (показатель 1.75, десять званий) давала максимум на 844 XP, тогда как контента примерно на 18 000: «Чемпион» закрывался за шесть глав из 137, и 95 % программы не двигали ничего. Калибровали её при двадцати двух главах и с тех пор не трогали. Теперь показатель 2.6 и пятнадцать званий, максимум 17 137 XP. У всех, кто учился на старой кривой, уровень стал ниже — прогресс не потерян, пересчитана шкала. Страж в `levels.test.tsx` считает доступный XP прямо из данных и требует, чтобы максимум лежал между 60 % и 120 % от него: вырастет контент — тест напомнит. Тесты, которым нужен порог уровня, берут его через `xpForLevel(2)`, а не числом.

**Число XP печатает `store.addXp`, а не компонент** (18.09.2026). Множитель серии поднимает начисление до ×1.5, и карточка с константой расходилась с тостом: «+20 XP» против «+30 XP» за одно действие. `addXp` возвращает фактически начисленное, все 34 места показывают возврат, а страж `scripts/xp-display.test.mjs` не даёт константе вернуться. Попутно ушло враньё постарше: показ был завязан на наличие `chapterId`, поэтому при повторном заходе тренажёр снова обещал XP, которых уже не дают.

**Группы построены целиком и в бою не использовались** (проверено 21.09.2026: в боевой базе 0 групп, 0 участников, 1 пользователь — сам Олег). Путь пройден вручную на локальном сервере за наставника и двух студентов: `DEV_LOGIN=1 MENTORS=teacher SESSION_SECRET=… DB_PATH=/tmp/… PORT=4599 BASE_URL=http://localhost:4599 node server/index.mjs`, дальше `/api/auth/dev-login?login=X` отдаёт токен во фрагменте `Location`. Создание группы, код, вступление, `PUT /progress`, сводка с покрытием по главам — работает всё. Прогресс шлётся именно `PUT` и телом-снимком без обёртки; ученик удаляется `POST /mentor/groups/:id/remove`, а не DELETE. Единственная дыра, которая нашлась: `myGroups` был написан и ни разу не вызван, поэтому вступивший по коду терял след группы при перезагрузке — теперь группы едут в `/me`. Страж в `server/groups.test.mjs` не даёт остаться мёртвому запросу про группы.

**Одна вкладка больше не стирает другую** (21.09.2026). `persist()` пишет ВЕСЬ снимок из памяти, и пока вкладка не знала о чужих записях, она откатывала всё сделанное в соседней — молча. Теперь store перечитывает хранилище по событию `storage` и при возврате на вкладку (замороженная в bfcache событие пропускает). Слиянием это НЕ лечится: `mergeProgress` объединяет «по лучшему», а в store есть настоящие удаления — избранное и пресеты воскресали бы.

**Пространства имён CSS плоские, и корни разъезжаются молча** (21.09.2026). Стили лежат в трёх общих файлах, попадают в одну сборку и не изолированы ничем: два компонента с одинаковым коротким корнем (`gb`, `tc`, `st`, `cc`) красят друг друга. За один день это выстрелило трижды. Худший случай: плашка игрового слоя заняла `.gb`, которым уже звался корень Конструктора тренажёров, — её `white-space: nowrap` растянул `<section>` Конструктора на 1886 px, и **весь /gym поехал вбок на проде**. Ни typecheck, ни vitest (рендерит компонент в одиночку), ни сборка этого не видят. Теперь под стражем `scripts/css-roots.test.mjs`. Он смотрит ВСЕ классы в `className`, а не первый: в «gym-section gb» виновник стоял вторым, и первая версия стража его пропустила. Общие классы С ДЕФИСОМ (`ac-card`, `keys-kbd`, `sc-option`) — наоборот, норма и намеренно переиспользуются; страж их не трогает. Разрешённые пересечения корней перечислены в нём же списком `РАЗРЕШЕНО`.

**Таблица рекордов показывала не то, что обещала** (21.09.2026). Под заголовком «Тренажёры» шли только механики, записавшие скорость, — их четыре из сорока шести, поэтому две сотни пройденных упражнений выглядели как потерянный прогресс. Теперь строка на каждый пройденный тренажёр, скорость там, где она есть, прочерк там, где её не бывает. Экзаменов по блокам в рекордах не было вовсе: `ChapterExam` пишет и в `exams`, и в `quizLog`, а `BlockExam` — только в `exams` под ключом `block:<id>`, мимо всех читателей. Они идут первыми строками таблицы квизов: обрезка в 25 строк иначе прятала бы их за проверками. Обе таблицы обрезаны — у прилежного студента там 664 строки.

**Достижение «Археолог» просило больше, чем трек даёт** (21.09.2026). Врезок «Как это было» всего восемь: четыре в фундаменте, три в мобилке, одна в блокчейне. При пороге 5 студент блокчейна обязан был найти ВСЕ доступные ему пять, а студент мобилки — пять из семи. Порог снижен до 4, страж `scripts/history-notes.test.mjs` считает врезки по трекам и требует запаса хотя бы в одну: допишутся врезки — порог можно поднимать.

**Тяжёлый `await import()` внутри теста падает по таймауту под полным прогоном** (21.09.2026). `store.test.tsx` грузил `DailyChallenge` (карта знаний, банк вопросов, React-дерево) прямо в теле теста: в одиночку 1.1 с, под всеми 227 файлами — больше пяти секунд, и тест падал, ничего не проверив. Выглядит как флейк, лечится переносом импорта в шапку файла: сборка модулей должна происходить до старта секундомера.

**Достижений 110, и лестница — это счёт РАЗНЫХ сущностей, а не длина журнала** (21.09.2026). Было 43, и почти каждая шкала обрывалась на второй ступени: квизы 1→10 при 664 квизах, тренажёры — только «первый» при 228 упражнениях, XP 100→500 при потолке 17 137. Хуже того, 35 из 43 обслуживали фундамент: у мобилки (46 глав) и углубления (9) не было НИ ОДНОГО. Теперь лестницы считаются по множеству `${chapterId}:${quizId}` и по ключам `s.trainers`, иначе один квиз, пересданный десять раз, закрывал бы ступень «десять квизов». Появились категории «треки», «мастерство», «вклад», пять скрытых (`hidden: true` — страница печатает «???») и мета-достижения; последние стоят В КОНЦЕ массива, потому что `snapshot()` отдаёт живой state и внутри одного прохода `evaluate()` видно только выданное выше. Страж в `achievements.test.tsx` требует, чтобы в ряду `N-имя` редкость не падала с ростом порога — он сразу поймал «500 XP редкое → 1000 XP обычное».

**Достижение платит XP, и печатает его на своей же плашке** (21.09.2026). Раньше наградой был только тост на семь секунд. Теперь `evaluate()` начисляет `RARITY_XP` по редкости (10/25/50, всего около 2 700 XP на все 110 при потолке 17 137) с детерминированным reason `ach:<id>`, поэтому повторный проход не платит дважды. Два следствия, на которых это ломалось: `evaluate()` крутится В ЦИКЛЕ, пока круг не окажется пустым, — награда сама открывает «Тысяча XP» и «Двадцать достижений», а один проход отложил бы их до следующего чиха в store; и у `AchievementsWatcher` появился свой гвард от вложенного вызова, иначе начисление XP поднимало событие `change` и «+10 XP» приезжал ОТДЕЛЬНЫМ тостом впереди достижения, за которое выдан. Отдельный тост про XP остался только за то, что заработано делом.

**Половина дороги, построенная с обеих сторон и не соединённая** (21.09.2026). Сервер принимал материал типа `preset` (объект с набором упражнений), каталог сообщества умел его нарисовать и запустить через `#preset=`, а отправить набор было НЕОТКУДА: в форме «Поделиться материалом» четыре типа и все со ссылкой, а `submitCommunity` во всём `src/` звался ровно в одном месте. На проде в каталоге лежало 0 пресетов при 24 материалах. Теперь в строке своего набора на /gym есть «В сообщество», а страж `scripts/community-types.test.mjs` сверяет `COMMUNITY_TYPES` сервера с тем, что интерфейс умеет отправить.

**Правила набора — в `server/preset.mjs`, и это единственный их экземпляр** (21.09.2026). Раньше кодек жил в `GymBuilder.tsx`, а сервер проверял «объект и не массив»: в базу могло лечь что угодно, включая лишние ключи и мегабайт карточек, и такая запись не проходила клиентский кодек уже ПОСЛЕ одобрения модератором — материал пропадал молча. Модуль без типов намеренно: его читают node, webpack и тесты (webpack путь `../../server/preset.mjs` из `src/` резолвит — проверено сборкой). В формате есть версия `v`, лимиты (100 карточек, 80 символов имени, 4000 кода) — набор целиком уезжает в снимок store и в `PUT /progress` с лимитом тела 1 МБ. Очередь модерации получила `summary` и показ первых строк: до этого модератор одобрял набор вслепую, видя только заголовок.

**Избранное хранит упражнение, а не ссылку на него** (21.09.2026). Раньше в звёздочку помещались только блок главы и слово, причём у тренажёра и квиза сохранялись лишь заголовок и якорь: вернуться можно было в главу, но не к упражнению. Теперь у `FavPayload` есть вариант `{ kind: 'preset' }` с данными движка — набор кладётся целиком и запускается прямо на /favorites, даже если карточку в каталоге сняли с публикации. Отмеченные слова из разных глав — уже готовый набор карточек: форма данных у избранного слова и у карточки движка одна и та же, поэтому «собрать тренажёр» это не конвертация, а прямая передача. `RunPreset` экспортирован из `GymBuilder`: второй экземпляр этого switch означал бы, что новый движок появляется в одном месте и молча отсутствует в двух других.

**Удаление наконец переживает синхронизацию: надгробия** (21.09.2026). `mergeFavorites` и `mergePresets` — объединение множеств, поэтому снятая звёздочка возвращалась с сервера через пять секунд после автосинка. Молча, и так каждый раз. В store появился `removed: { id, ts }[]`, и слияние отбрасывает то, что убрано ПОЗЖЕ, чем добавлено. Дата обязательна — на этом первая версия и упала в собственном тесте: надгробие живёт на сервере, и без сравнения по времени оно запрещало бы добавить то же самое заново навсегда. Список подрезан до 500 последних записей с обеих сторон.

**Проверка ссылки ходит от имени ХОСТА, а не браузера студента** (21.09.2026). `checkLink` брал любой https-адрес от любого вошедшего и следовал редиректам — то есть форма «поделиться материалом» работала зондом во внутреннюю сеть сервера и в облачную метаданную `169.254.169.254`. Теперь перед запросом имя разрешается и проверяется: приватные, loopback, link-local и v4-в-v6 адреса отбиваются, а редиректы разматываются ВРУЧНУЮ (не больше трёх) — `redirect: 'follow'` проверял бы только первый адрес, а увести внутрь можно вторым. Резолвер имён приходит параметром, как и fetch: иначе тесты стали бы зависеть от сети и от того, куда чужой домен указывает сегодня.

**Роль — это не право, и до 21.09.2026 сервер их путал.** Разбор перед публичным API нашёл четыре дыры, ни одну из которых не видел ни один тест. (1) `GET /mentor/students` без `?group` отдавал `allUsers` — любой наставник выгружал ВСЮ базу платформы с логинами, аватарами и разобранным прогрессом, включая чужие группы; теперь без фильтра видно только своих, а всю платформу — только корневому наставнику из `.env`. (2) `DELETE /mentor/results/:id/:module` позволял любому наставнику стереть результат любого человека, необратимо; теперь только своему ученику. (3) Раздавать роли (`/mentor/mentors`, `/content/authors`, `/moderate/people`) мог любой наставник, включая только что добавленного, — цепочка «наставник → назначил себя автором → коммит в main → деплой на прод» замыкалась без участия владельца; теперь только корневой. (4) `readBody` при переполнении лимита только реджектил промис: слушатель оставался, клиент продолжал лить тело, строка росла — лимит не ограничивал ничего, кроме ответа; теперь считаются байты и соединение рвётся. Всё это под живым стражем `server/permissions.test.mjs` — он поднимает настоящий сервер, потому что запросами это единственный способ проверить.

**Сводка наставника считала квизы по числу записей** (21.09.2026) — ту же ложь, что и шапка главы: проваленная проверка шла наравне с безошибочной. Теперь `countPerfect`: `correct === total`, как в сосуде.

**Публичное API: ключ не ходит в кабинет, и это главное свойство модели** (21.09.2026). Ручек в кабинете сорок, и охраны там проверяют РОЛЬ, а не право: `mentorGuard` пускает любого наставника независимо от того, какие права выданы ключу. Поэтому `bearer()` ОТВЕРГАЕТ токены с префиксом `pgk_` вовсе, а ключи ходят только по `/api/v1/*` из белого списка `server/api-routes.mjs`. Чего нет в списке — того нельзя: там нет ни одного DELETE, нет записи прогресса и результатов (сервер их не проверяет — это слова клиента), нет раздачи ролей. Права ключа пересчитываются НА КАЖДОМ запросе как пересечение выданных с теми, что даёт живая роль владельца: сняли роль автора — `content:write` умер в ту же секунду. Ключ ищется в базе по SHA-256 хешу, поэтому отзыв мгновенный (у сессионного токена отзыва нет вовсе — он живёт 180 дней). `content:write` пишет в ОТДЕЛЬНУЮ ветку и возвращает ссылку на pull request: `main` деплоится на прод, а неверный `.mdx` роняет сборку и блокирует выкладку всего сайта.

**Документация API генерится, а не пишется** (21.09.2026). `static/api.md` (он же `https://edu.alspio.com/api.md`) собирается из того же белого списка, что обслуживает запросы, шагом `prebuild`. Страж сверяет файл с генератором. Важная деталь: генератор пишет файл ТОЛЬКО при прямом запуске — первая версия писала его на импорте, и тест, импортировавший генератор, сам перезаписывал то, что собирался проверить.

**Сырой `.md` из `static/` сервер отдаёт как `application/octet-stream`** (21.09.2026) — то есть по ссылке он СКАЧИВАЕТСЯ, а не открывается. Поэтому документация API живёт в двух файлах из одного текста: `static/api.md` для машины (curl, «вставь модели») и `src/pages/api.md` для человека по адресу `/api`. Оба пишет генератор, оба сверяет страж. Пункт в навигации ведёт на страницу, а не на сырой файл.

**Тренажёр в зале открывается НАД сеткой, а не внутри карточки** (21.09.2026). Механика запускалась прямо в своей ячейке грида: клавиатурный тренажёр и терминал ужимались в колонку 322 px, а четыре соседние карточки растягивались до высоты запущенного и стояли пустыми. Теперь запуск поднимает механику в сцену на всю ширину (992 px на десктопе), карточка показывает «Идёт наверху ↑», а `key={component}` заставляет движок начаться заново при переключении.

**Награда-кастомизация не хранит факт «открыто» — она его ВЫЧИСЛЯЕТ** (21.09.2026). Облик (тема сосудов + акцент «твоё») висит на уже выданном достижении: `src/lib/looks.ts`, применяется в `Root.tsx` через `effectiveLook(выбранный, выданные)`. Это не экономия кода. `prefs` сливается на сервере ПОВЕРХНОСТНО (`server/merge.mjs`), по ключу побеждает последняя синхронизация и отката нет — флаг «куплено» там теряется, а достижение нет. Валюты и магазина нет намеренно: вторая шкала дала бы повод соревноваться за объём, тогда как достижения проверяют качество. В хранилище едет только выбор (`prefs.skin`), и он проверяется белым списком на ЧТЕНИИ.

**У закрытой награды обязан быть видимый путь.** Витрина достижений печатает только условие, поэтому «25 тренажёров» молчит про «у тебя 18» — к такой награде не идут. У каждого облика есть `progress()`, и страж требует, чтобы его мера совпадала с мерой достижения: иначе полоса покажет «6 из 6», а облик останется закрытым.

**Обложка красится СВОИМИ токенами, а не палитрой.** `--pgk-cover-a/-b/-accent` (src/css/custom.css) по умолчанию указывают на те же значения палитры, что стояли в компоненте раньше, поэтому без облика ничего не изменилось; облик перекрывает только их. Красить `--ifm-color-primary` было нельзя: 274 обращения по src — это ссылки, кнопки и подсветка кода. Токена три, а не один, потому что иллюстрация обложки тоже берёт акцент: поменяй только градиент — и на зелёном фоне остались бы индиговые детали. Страж в `css-roots.test.mjs` требует, чтобы заслуженный облик задал ВСЕ поверхности: облик, поменявший полосу и забывший обложку, читается как поломка.

**Акцент облика задаётся ПАРОЙ правил на тему.** `--pgk-you` в светлой теме `#b4550f`, в тёмной `#ffb05c`; одиночный `[data-skin=…]` имеет ту же специфичность, что `[data-theme='dark']`, и исход решал бы порядок импорта файлов. Два атрибута разом (`[data-theme='dark'][data-skin='…']`) дают специфичность выше обоих. Палитру платформы (`--ifm-color-primary` и шесть оттенков, 274 обращения) облик не трогает: это ссылки, кнопки и подсветка кода.

**Печать носится, а не хранится как право** (21.09.2026). `prefs.seal` — это id достижения, и всё; можно ли его носить, решает `effectiveSeal(выбранный, выданные)` на каждом показе. Модуль отдельный от `looks.ts` не из вкуса: печати нужен реестр достижений, реестр импортирует store, а store импортирует `looks.ts` за списком обликов — положи печать туда, и кольцо замкнулось бы. Печать «пройдено» на обложке главы считает `isFull(chapterId)`, поэтому обложке понадобился `position: relative`: абсолютная печать иначе улетела бы к ближайшему позиционированному предку, то есть на всю страницу.

**У закрытой ступени видно, сколько осталось** (21.09.2026). Витрина печатала только условие — «25 тренажёров» и молчание про «у тебя 18», а к невидимой награде не идут. Порог ступени уже зашит в её id, поэтому progress проставляется автоматически по СЕМЕЙСТВУ: семнадцать счётчиков в `LADDER` вместо функции у каждой из сорока с лишним ступеней. Страж требует, чтобы счётчик мерил то же, что проверка: догоняет счётчик до порога и требует, чтобы `check` в этот момент сработал, а на шаг раньше — нет. Иначе полоса показывала бы «25 из 25» при закрытом достижении.

**Прохождение набора засчитывается, и ключ берётся от СОДЕРЖИМОГО** (21.09.2026). Раньше чужой набор не давал ни XP, ни отметки, ни строки у наставника — проходить его было незачем. Теперь три движка из четырёх получают `chapterId='gym'` и `trainerId=preset:<хеш>`; у карточек слов момента «сделано» нет, их листают, поэтому там отметки и нет. Хеш считается по нормализованному содержимому (`src/lib/presetKey.ts`), а НЕ по id пресета: id вида `cp-<время>-<случайное>` меняется при каждом пересохранении, а `addXp` платит один раз за причину — то есть XP фармился бы копией того же набора. Побочно: набор из каталога и он же со своей полки дают один ключ, а значит одну запись в прогрессе. Карточка ученика теперь отдаёт и сами id (`trainerIds`): у зала под одним chapterId лежат и механики, и наборы, и «пять тренажёров» не отвечало на вопрос «прошёл ли он выданный набор».

**Автор материала наконец узнаёт его судьбу** (21.09.2026). Он отправлял в каталог и больше не видел ничего: ни «принято», ни «отклонено» не показывалось нигде, поэтому человек либо считал, что его проигнорировали, либо присылал то же самое второй раз. Появилась ручка `GET /community/mine` (свои записи со статусом) и блок «Моё» на /community. След пишется и в store — `community: string[]` с метками `sub:<id>` и `ok:<id>`: ОДИН массив, а не объект с двумя полями, потому что тогда работает то же слияние объединением, что и у `xpAwarded`, а достижения «Поделился» и «Приняли» читают его по префиксу и считаются без сети.

**«Добавить всех в группу» — только владельцу платформы, не владельцу группы** (23.09.2026). `POST /mentor/groups/:id/add-all` проверяет `isRootMentor`, а не `canManageGroup`: если бы это было доступно любому владельцу своей группы, ЛЮБОЙ наставник мог бы одним запросом затащить к себе в группу всех зарегистрированных студентов платформы — та же дыра в приватности, что фикс «роль — не право» от 21.09.2026 закрыл для `/mentor/students`, только через другую дверь. Владелец группы не добавляется в неё сам (`row.gh_id === g.owner` пропускается): иначе наставник оказался бы студентом собственной группы. Идемпотентно — `addMember` уже `INSERT OR IGNORE`, повторный вызов возвращает `added: 0`.

**Главная страница знает о студенте — но только после проверки, что он реально начал** (23.09.2026). `HomeHero.tsx` раньше не импортировал `store` вовсе: витрина не менялась ни на йоту для того, кто уже прошёл половину трека. Признак «начал» — `Object.keys(store.snapshot().sections).length >= 1`, ровно та же проверка, что у достижения «Первая прочитанная глава». `nextChapter()` сюда НЕ годится сама по себе: она всегда возвращает первую нетронутую главу и потому не отличает «здесь ещё никого не было» от «читает первую главу» — на пустом сторе вернула бы `github-start` точно так же, как настоящему новичку. Трек берётся из уже сохранённого `prefs.track` (см. запись про Маршрут выше) с тем же умолчанием «мобилка», что и там: студент фундамента мог накопить прогресс, ни разу не выбрав трек руками. До монтирования (и любому подлинно новому гостю) первый экран выглядит ровно как раньше — тот же `mounted`-guard, что у остальных SSR-чувствительных мест платформы.

**Мера строки била только по ПРЯМЫМ детям `.markdown`** (22.09.2026). `.markdown > p` не доставало до текста внутри подсказок (их 510 в главах), складок и цитат: при колонке 868 px соседние абзацы шли 734 и 831 — один и тот же основной текст, разной длины строки. Это не настройка, а баг вёрстки; чинится расширением селектора. Таблицы, код и тренажёры в меру намеренно не входят — им ширина нужна вся.

**Кегль ставится ДО отрисовки, иначе каждая загрузка начинается с перекладки** (22.09.2026). `Root.tsx` штампует атрибуты в `useEffect`, то есть после гидратации: для облика это незаметно, для размера текста — это прыжок всей страницы на каждой загрузке. Поэтому в `headTags` (docusaurus.config.ts) добавлен восьмистрочный скрипт, читающий `localStorage` до первой отрисовки, — так же поступает сам Docusaurus со светлой и тёмной темой. Ключ хранилища там продублирован строкой (импортировать модуль в конфиг нельзя) и держится стражем `scripts/read-stamp.test.mjs`. Потолок кегля 125 %: выше начинают обрезаться подписи в тренажёрах, у которых холсты заданы в пикселях.

**Профиль в шапке кешируется, иначе каждая загрузка страницы начинается с пустоты** (24.09.2026). `/me` быстрый (SQLite без сети), но нулевой сетевой задержки не бывает, а `AccountNav` до ответа рисовал `null` — на каждой полной загрузке аватар вошедшего появлялся с заметным опозданием. Последний профиль кладётся в `localStorage` (`pgk-profile-cache`) при каждом успешном `fetchProfile()` и рисуется немедленно при следующей загрузке; сеть всё равно сверяет и обновляет следом. Кеш чистится при 401 и при `logout()` — иначе после выхода на секунду мелькал бы чужой уже невалидный профиль.

**Заметка наставника об ученике — своя, и она ДОБАВКА к нику, а не замена** (24.09.2026). `mentor_notes(mentor_gh_id, student_gh_id, note)` — заметка видна только тому наставнику, который её поставил: у другого наставника того же ученика заметки нет вовсе, сверять их незачем. Ставить может только `isRootMentor` или тот, кто реально ведёт ученика (`teaches()`) — та же охрана, что у удаления результата. Первая версия витрины заменяла ник именем из заметки целиком, и наставник, ведущий группу по факту `@login`, терял способ свериться, кто есть кто на платформе. Теперь ник всегда виден — второй строкой под именем в списке учеников (класс `mn-name-stack`), или отдельной строкой `@login` в карточке ученика, где она была и раньше.

**Поиск по площадке: язык индекса — НЕ язык интерфейса** (24.09.2026). Локальный `@easyops-cn/docusaurus-search-local` вместо Algolia — работает офлайн, без стороннего аккаунта и краулера. С `language: ['ru']` запросы кириллицей находили всё честно (со всеми падежами), а термины латиницей (Gradle, RecyclerView, GitHub) — НИЧЕГО: искал не пустой список, а неотфильтрованную «витрину» первых документов индекса, что выглядело как рабочий поиск с случайными результатами, а не как поломка. У платформы половина текста кириллицей, половина технических терминов — латиницей, поэтому `language: ['ru', 'en']` — оба стеммера сразу, индекс на ~13% больше (17,5 МБ вместо 15,5), но грузится лениво (проверено: ни один запрос к `search-index.json` не уходит до фокуса в поле поиска) и только один раз за сессию. Перевод интерфейса (`theme.SearchBar.*`, `theme.SearchPage.*`) вписан в `i18n/ru/code.json` руками: `docusaurus write-translations` заодно генерит 350+ строк по всему сайту с английскими значениями по умолчанию — брать из этого вывода нужно только ключи поиска, а не весь файл целиком.

**Рейтинг вклада в сообщество считает по `community`, а не по стору** (24.09.2026). `store.community` (метки `sub:<id>`/`ok:<id>`) — это только СВОИ отметки вошедшего, без сети чужой вклад посчитать нельзя. `GET /community/leaderboard` — публичный агрегат (`GROUP BY author_gh_id`, джойн на `users` за живым аватаром — снимок `author_login` в `community` не обновляется задним числом), сортировка по числу ПРИНЯТЫХ материалов, а не отправленных: отправить можно что угодно, а вклад в каталог — то, что прошло проверку. Достижения «Поделился»/«Приняли» (за первый раз) не тронуты — сверху добавлена лестница `3/10/25-принятых-материалов` с отдельным счётчиком `acceptedMaterials()`, считающим МНОЖЕСТВО принятых id, а не длину `community` (там же лежат и метки `sub:`, и задним числом принятая пересылка не должна закрывать ступень выше единицы).

**`GET/PUT /api/v1/chapters/:id` были сломаны почти на каждой главе — `path` не файловый путь** (25.09.2026). `path` в knowledge-map.json — это URL-слаг БЕЗ числового префикса (Docusaurus сам режет его у ссылок при сборке сайта), а сервер строил из него `docs/${ch.path}` и просил у GitHub содержимое главы по ЭТОМУ адресу. Для главы «typing» это значило запрос `docs/foundation/typing.mdx`, которого не существует — реальный файл `01-typing.mdx`. Так было почти у всех 137 глав, кроме считаных случаев вроде `02b-english-practice`, где префикс не строго числовой и потому не срезается вовсе. Нашлось не тестом, а первым же внешним потребителем (плагин для Android Studio, тянущий словарь главы через `content:read`) — ни один гейт эту пару ручек не трогает вообще, потому что это единственное место в API, где содержимое реально ходит на GitHub и обратно. Чинить реконструкцией вида `${num}-${path}` было НЕЛЬЗЯ: у части глав `docs/advanced/*` `num` чисто декоративный (для обложки) и не совпадает вообще ни с каким префиксом файла — так сломались бы 7 глав из 137, просто по другой причине. Решение — новое поле `file` в knowledge-map.json: настоящее имя файла на диске, с префиксом, записанное `scripts/knowledge-map.mjs` В ТОЙ ЖЕ точке, где раньше префикс молча срезался (само значение уже было в переменной, просто нигде не сохранялось). Страж в `knowledge-map.test.mjs` проверяет `fs.existsSync` по ВСЕМ 137 главам, а не по выборке — семь исключений выше на выборке не ловятся.

**`/edit` этой болезнью не болеет** — он вообще не читает knowledge-map.json для определения пути к файлу. `/content/meta` берёт список файлов из git-дерева GitHub напрямую (`git/trees/<branch>?recursive=1`), а `/content/file` принимает путь от клиента и проверяет только регуляркой `SAFE_DOC_PATH` — настоящий путь узнаётся из самого GitHub, а не выводится из чужого поля задним числом.

**Ширина текста в схемах и обложках.** SVG не переносит текст. Единственная надёжная проверка — настоящий `getBBox()` против `viewBox`. Оценка «на глаз по длине строки» врёт.

**Живые ссылки.** Внешние URL проверять `curl`, видео — только через oEmbed (см. §9).

## 9. Правило фактуры: живой прогон, не по памяти

Каждый пример кода, каждое сообщение компилятора и каждый вывод программы в главе **сняты вживую в этой же сессии**. Не по памяти, не «примерно так».

- **Kotlin:** `POST https://api.kotlinlang.org/api/2.4.10/compiler/run?filename=File.kt`. JVM плейграунда — 17.0.20.
- **TypeScript:** локально `npx tsc --noEmit --strict …` (сейчас 6.0.3), запуск — `node file.ts` напрямую: Node 24.14.1 сам срезает типы.
- **Видео:** кандидатов набирать поиском YouTube (`user-agent: Mozilla/5.0`, регексом по `videoRenderer`), затем **обязательно** проверять каждый через oEmbed:
  `https://www.youtube.com/oembed?format=json&url=…` — не 200 значит мёртвое или приватное. Так отсеялось `AkL7uFm8ze4`, которое выглядело живым.
- Коды ошибок TS (`TS2322`, `TS18047`, …) и тексты Kotlin копируются из реального прогона.

## 11. Ловушки среды

- **Новый модуль сервера надо ещё и положить в образ.** `server/Dockerfile` раньше копировал файлы поимённо (`COPY index.mjs merge.mjs`). 16.09.2026 новый `linkcheck.mjs` доехал на сервер, но не попал в контейнер, и кабинет лёг целиком: 502 на всём, включая `/health`. Теперь `COPY *.mjs`. Если понадобится не-`.mjs` файл — проверить, что он в образе, а не только в `server/`.
- **«Docusaurus found broken anchors» на /gym — ложная тревога, но не вся.**
  Проверяльщик якорей знает только якоря заголовков и не видит `id`, который
  `<Block>` рендерит из `blockId`. Поэтому 31 ссылка Зала помечается битой,
  хотя все 144 ссылки с якорем реально резолвятся в собранном HTML (сверялось
  по `build/**/index.html` 17.09.2026). Гасить это `onBrokenAnchors: 'ignore'`
  нельзя — потеряется настоящая проверка ссылок на заголовки. ВАЖНО: когда
  предупреждений станет больше 31, это уже не шум. Так нашлись 84 настоящих
  битых ссылки: у блоков печати нет атрибута `blockId`, а генератор подставлял
  туда `trainerId` — `<Block>` без `blockId` не рендерит `id` вовсе. Теперь
  реестр в таком случае пишет `null`, ссылка ведёт на главу, и это под стражем.
- **HTML сборки минифицирован, атрибуты без кавычек.** В `build/**/index.html`
  лежит `id=trainer-bug-hunt`, а не `id="trainer-bug-hunt"`. Греп вида
  `id="[^"]*"` не находит НИЧЕГО и выглядит как «элемента нет». Искать
  `\bid=(?:"([^"]+)"|([A-Za-z0-9_:.-]+))`.
- **JS-прокрутка в панели браузера не работает.** `window.scrollTo` и
  `scrollIntoView` не двигают страницу (`scrollY` остаётся 0), хотя настоящее
  колесо через `computer {action:'scroll'}` двигает. Переход по якорю при этом
  проверяется присвоением `location.hash` — оно срабатывает.
- **Ленивые картинки в скрытой панели не грузятся никогда.** Панель не рисует кадры, пересечения с областью видимости не происходит, `loading="lazy"` не срабатывает. Проверять через `new Image()` или показав панель.
- **Сначала спроси, едет ли страница ВООБЩЕ.** `document.documentElement.scrollWidth > clientWidth` — единственный ответ на вопрос «есть ли горизонтальная прокрутка». Только если да, ищи виновника по правому краю. Иначе получишь гору ложных: на главе 17.09.2026 перебор по правому краю выдал 113 «переполнений» (таблицы, код, `sb-part`), а страница вбок не ехала вовсе — всё это живёт внутри своих прокручиваемых обёрток, и так задумано.
- **Переполнение страницы ищут по правому краю, а не по `scrollWidth`.** У элементов с `text-overflow: ellipsis` `scrollWidth` всегда больше бокса — это норма, а не переполнение. Виновника выдаёт `getBoundingClientRect().right > clientWidth`; так нашёлся `<select>` фильтра, растянутый под самое длинное название главы.
- **cwd сбрасывается между вызовами Bash.** Каждая команда начинается с `cd …/platform &&`. Ловилось многократно.
- **zsh калечит кириллицу в подстановке команд.** Разбор JSON — внутри `node --input-type=module`, не в шелле.
- **Скрытая панель не проигрывает переходы.** Если панель не показана, страница не рисует кадры: CSS-`transition` не двигается, и `getComputedStyle` НАВСЕГДА отдаёт стартовое значение. Выпадающее меню с `opacity 0 → 1` выглядит сломанным, хотя каскад верный. Проверять так: `el.style.transition='none'` + перевесить класс + мерить. Съело полчаса 15.09.2026.
- **После смены темы ждать, пока доиграет `transition`.** Если у измеряемого свойства есть переход (у `.cp-cell` это `background 0.15s`), `getComputedStyle` сразу после флипа `data-theme` отдаёт ПРОМЕЖУТОЧНЫЙ кадр. Дважды 17.09.2026 это выглядело как «в светлой теме цвет остался тёмным»: читалось `rgb(91,103,130)`, а через 2.5 с — честные `#d8dfec`. Мерить после выдержки или с `transition:'none'`.
- **`getComputedStyle` возвращает ЖИВОЙ объект.** Сохранить его и прочитать поля позже — значит прочитать состояние на момент чтения, а не на момент съёмки. Снимать значения сразу в обычный объект.
- **Панель браузера бывает скрыта:** скриншоты выходят пустыми, а `window.innerWidth` крошечный, поэтому `scrollWidth > innerWidth` даёт ложное «переполнение». Перед любым замером — `resize_window` (1280 и 375), проверять через `javascript_tool` / `read_page`.
- **Замер всех глав разом:** одним `javascript_tool` — `fetch` каждой страницы, `DOMParser`, вставка SVG в скрытый `position:absolute;left:-9999px;width:900px` div, потом настоящий `getBBox()`. Ходить по каждой главе не нужно.
- **Откуда брать собранные страницы для замера:** `preview_start {name:"edu-build"}` — статический сервер на 8795 поверх `build/`, конфигурация лежит в `~/Documents/claude/.claude/launch.json` (не в репозитории). Дальше один `javascript_tool` с `fetch` + `DOMParser` + `getBBox`.
- **Субагенты делят браузер с основной сессией** — их замеры уезжают на чужую страницу. Субагентам запрещено: dev-серверы, сборки, тесты, коммиты.
- Дев-сервер поднимать только через Browser pane (`preview_start`), не через Bash.
