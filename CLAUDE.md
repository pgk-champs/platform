## 1. Что это

- Пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) → сборка с гейтами → rsync на VPS. Отдельной команды деплоя нет: **выложить = запушить в main**.

## 3. Правила работы

- **Решай сам** всё, что касается «как» — структура главы, формулировки, вёрстка схем, выбор примеров.
- **Спрашивай** про «что» — какую тему писать, какой трек двигать, что переделывать. Это доска, а не догадки.
- Не спрашивай разрешения на перезапуск локальных сервисов и на коммит рутинной работы — это шум.
- Дизайн: показывай **варианты**, а не вопросы «как сделать».

## 5. Контракт «добавить главу»

Глава подключается к сайдбару сама, но **шесть мест надо тронуть руками**. Пропустишь — падает гейт или, хуже, ничего не падает и глава тихо неполноценна.

1. **`docs/<трек>/NN-slug.mdx`** — фронтматтер обязателен целиком:
   ```yaml
   title: '…'
   audience: 'все' | 'мобилка' | 'блокчейн'   # другие значения → kmap падает
   level: 'база' | 'углубление' | 'челлендж'
   order: N
   ```
2. **`src/components/figures/<модуль>.tsx`** — 2–5 схем + рядом `<модуль>.test.tsx`.
3. **`Figure.tsx`** — импорт модуля **и** спред в `SCHEMES` (две строки).
4. **`Figure.test.tsx`** — импорт **и** `...Object.keys(<модуль>Schemes)` (две строки). Тест сверяет `SCHEME_IDS.length === all.length`, поэтому забыть нельзя.
5. **`ChapterCover.tsx`** — запись в `ART` (svg-арт) и в `CHAPTERS` (`{ track, num, title }`), плюс поднять счётчик в `ChapterCover.test.tsx` (`toHaveLength(43)`).
6. **`src/data/chapter-videos.json`** — ровно 4–5 видео, и **3–7 вопросов** в `DAILY_BANK` (`DailyChallenge.tsx`). Глава без вопросов роняет vitest: `CHAPTER_META` строится из карты знаний.

**Перенумеровать главы внутри трека безопасно** — числовой префикс в URL не попадает. Ломаются только `num` в `CHAPTERS` и его тест. Переименовывать файлы **обратным порядком** (13→ сначала, потом 12), иначе `mv` попадёт в существующее имя.

**`chapterId` менять нельзя.** К нему привязаны прогресс, избранное, XP, словарь, вопросы дня и дашборд наставника — а не к пути. Переезд главы между треками дёшев, смена `chapterId` — нет.

## 6. Из чего состоит глава (канон v2+)

Обязательный минимум, его проверяют стражи:

- `<ChapterCover chapterId="…" />` сразу после фронтматтера;
- `<ChapterProgress chapterId totalSections totalQuizzes totalTrainers />`;
- 2–5 `<Figure>`, ровно один `<ChapterExam>`, 4–5 видео;
- `<SectionAnchor>` в **конце** каждой секции (метка «секция прочитана» стоит после текста, не до);
- `<Hint type="tip" | "important" | "fact">` — **других значений нет**, невалидное падает только на `build`;
- `<Block kind="trainer" | "quiz" | "breakdown" | "vocab" | "cheatsheet" | "fact">`.

Содержательные требования калибровки Олега: посимвольный `SyntaxBreakdown` на каждую новую конструкцию, каждый символ объяснён при первом появлении, построчный разбор примеров, секция «Типичные ошибки» с **настоящими** текстами компилятора, `SelfCheck` после каждой крупной секции, объём не режется ради краткости, каждый пример исполняемый (`KotlinPlay`).

## 7. Инварианты, которые НЕ ловит ни один тест

Это самое ценное в файле. Всё остальное поймает CI.

**`ChapterProgress` — арифметика не проверяется ничем.**
`totalSections` обязан равняться числу `<SectionAnchor>`, `totalQuizzes` — числу `<SelfCheck>` (**`ChapterExam` не считается**), `totalTrainers` — числу блоков `kind="trainer"`. Компонент делает `Math.min`, поэтому:

- завысил → полоса **никогда** не дойдёт до 100 %, и об этом никто не узнает;
- занизил → лишние прохождения молча теряются.

**Проверять только счётом на собранной странице.** Ровно так и был пойман баг в `kotlin-null`: заявлено 4 квиза, написано 3.

**Ширина текста в схемах и обложках.** SVG не переносит текст. Единственная надёжная проверка — настоящий `getBBox()` против `viewBox`. Оценка «на глаз по длине строки» врёт.

**Живые ссылки.** Внешние URL проверять `curl`, видео — только через oEmbed (см. §9).

## 8. Гейты и что каждый ловит

```bash
npm run kmap        # фронтматтер: обязательные поля и допустимые значения
npm test            # 8 тестов node --test: 5 стражей глав + 3 юнита карты знаний
npm run typecheck   # tsc
npx vitest run      # 119 файлов / 727 тестов
npm run build       # ЕДИНСТВЕННОЕ, что ловит невалидный <Hint type>
```

CI гоняет `npm ci && npm test && npm run test:ui && npm run build` (`kmap` едет внутри `prebuild`).

Пять стражей в `chapter-ids.test.mjs`: `chapterId` ↔ id карты знаний · экзамен в каждой главе · 2–5 `Figure` · валидный `Hint type` · 4–5 видео на главу.

**Ни один гейт не смотрит на отрендеренную страницу.** Всё из §7 — вручную, в браузере.

## 9. Правило фактуры: живой прогон, не по памяти

Каждый пример кода, каждое сообщение компилятора и каждый вывод программы в главе **сняты вживую в этой же сессии**. Не по памяти, не «примерно так».

- **Kotlin:** `POST https://api.kotlinlang.org/api/2.4.10/compiler/run?filename=File.kt`. JVM плейграунда — 17.0.20.
- **TypeScript:** локально `npx tsc --noEmit --strict …` (сейчас 6.0.3), запуск — `node file.ts` напрямую: Node 24.14.1 сам срезает типы.
- **Видео:** кандидатов набирать поиском YouTube (`user-agent: Mozilla/5.0`, регексом по `videoRenderer`), затем **обязательно** проверять каждый через oEmbed:
  `https://www.youtube.com/oembed?format=json&url=…` — не 200 значит мёртвое или приватное. Так отсеялось `AkL7uFm8ze4`, которое выглядело живым.
- Коды ошибок TS (`TS2322`, `TS18047`, …) и тексты Kotlin копируются из реального прогона.

## 10. Коммиты, секреты, деплой

- **Коммит не упоминает Claude, AI и соавторство.** Сообщение — по-русски, от лица Олега: что изменилось и почему.
- **Перед коммитом грепнуть диф** на ключи/пароли/IP:
  ```bash
  git diff HEAD | grep -nEi "(-----BEGIN|api[_-]?key|secret|passw|ssh-rsa|AKIA|xox[baprs]-)"
  ```
  Ложные срабатывания бывают (`#secret` в тексте про приватные поля JS) — смотреть глазами, не по счётчику.
- Прогнать **все пять гейтов** до пуша. Пуш в `main` = публикация на прод.
- В репозитории не должно оказаться ни `.env`, ни ключей: секреты живут в GitHub Secrets (`EDU_HOST`, `EDU_SSH_KEY`) и в `/opt/edu-alspio/.env` на сервере.

## 11. Ловушки среды

- **cwd сбрасывается между вызовами Bash.** Каждая команда начинается с `cd …/platform &&`. Ловилось многократно.
- **zsh калечит кириллицу в подстановке команд.** Разбор JSON — внутри `node --input-type=module`, не в шелле.
- **Панель браузера бывает скрыта:** скриншоты выходят пустыми, а `window.innerWidth` крошечный, поэтому `scrollWidth > innerWidth` даёт ложное «переполнение». Перед любым замером — `resize_window` (1280 и 375), проверять через `javascript_tool` / `read_page`.
- **Замер всех глав разом:** одним `javascript_tool` — `fetch` каждой страницы, `DOMParser`, вставка SVG в скрытый `position:absolute;left:-9999px;width:900px` div, потом настоящий `getBBox()`. 43 навигации не нужны.
- **Субагенты делят браузер с основной сессией** — их замеры уезжают на чужую страницу. Субагентам запрещено: dev-серверы, сборки, тесты, коммиты.
- Дев-сервер поднимать только через Browser pane (`preview_start`), не через Bash.
