## 1. Что это

- Docusaurus 3.10.2, TypeScript, статика.
- Единственный живой адрес — **https://edu.alspio.com**. GitHub Pages выключен.
- Пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) → сборка с гейтами → rsync на VPS. Отдельной команды деплоя нет: **выложить = запушить в main**.

- **Kotlin-факты, снятые вживую 13.09** (пригодятся в других главах): `readLine()` помечена устаревшей **начиная с 2.1.0** (на 2.0.21 предупреждения нет — проверено по пяти версиям); нажатый Enter даёт `""`, а не `null`; `readln()` после конца ввода бросает `kotlin.io.ReadAfterEOFException: EOF has already been reached`; `" 42 ".toIntOrNull()` → **null**, а `toDoubleOrNull()` → 42.0; `"3,5"` не читается ни тем, ни другим; `"%.2f".format` даёт **1234,50** при локали ru_RU и **1234.50** при en_US — локаль плейграунда `en_US`, локальной машины `ru_RU`, так что проверка формата в плейграунде НЕ доказывает поведение на устройстве.
- **Плейграунд не даёт stdin:** `readlnOrNull()` там всегда `null`. Примеры с вводом делаются исполнимыми через подмену чтения заготовленным списком строк. ## 3. Правила работы

- **Решай сам** всё, что касается «как» — структура главы, формулировки, вёрстка схем, выбор примеров.
- **Спрашивай** про «что» — какую тему писать, какой трек двигать, что переделывать. Это доска, а не догадки.
- Не спрашивай разрешения на перезапуск локальных сервисов и на коммит рутинной работы — это шум.
- Дизайн: показывай **варианты**, а не вопросы «как сделать».

## 5. Контракт «добавить главу»

Глава подключается к сайдбару сама, и **четыре места надо тронуть руками**. Трек, номер и заголовок обложки, а также знаменатели прогресса выводятся из файла — дублировать их больше негде и незачем (было шесть мест, половина — переписывание одного и того же; убрано 15.09.2026).

1. **`docs/<трек>/NN-slug.mdx`** — фронтматтер обязателен целиком:
   ```yaml
   title: '…'
   audience: 'все' | 'мобилка' | 'блокчейн'   # другие значения → kmap падает
   level: 'база' | 'углубление' | 'челлендж'
   order: N
   ```
2. **`src/components/figures/<модуль>.tsx`** — 2–5 схем + рядом `<модуль>.test.tsx`.
3. **`Figure.tsx`** — импорт модуля **и** спред в `SCHEMES` (две строки).
4. **`Figure.test.tsx`** — импорт **и** `...Object.keys(<модуль>Schemes)` (две строки). Тест сверяет `SCHEME_IDS.length === all.length`, поэтому забыть нельзя.
5. **`src/data/chapter-videos.json`** — ровно 4–5 видео, и **3–7 вопросов** в `DAILY_BANK` (`DailyChallenge.tsx`). Глава без вопросов роняет vitest: `CHAPTER_META` строится из карты знаний.

Арт обложки в `ChapterCover.tsx` (`ART`) — по желанию: без своей записи подставится арт трека.

**Простая страница — не глава.** Памятке, объявлению или разбору задания хватает `kind: 'page'` во фронтматтере: ни обложки, ни экзамена, ни схем, ни видео, ни вопросов дня. Стражи глав её намеренно не видят, в `knowledge-map.json` она не попадает (иначе ждали бы нулевой главой в зале и в дашборде — на этом упала сборка 15.09.2026), а лежит в `pages.json`. В маршруте показывается отдельным блоком «Страницы» — без галочки и статуса.

**Страницу заводят прямо на сайте** — `/edit`, роль автора выдаёт наставник. Правка идёт коммитом через GitHub Contents API (`CONTENT_TOKEN` в `/opt/edu-alspio/.env`), путь проверяется регуляркой `SAFE_DOC_PATH` — она под отдельным тестом `server/content-path.test.mjs`, ослаблять нельзя: тем же запросом можно было бы переписать код сервера или workflow деплоя.

**Главу из редактора завести НЕЛЬЗЯ, и выбор типа там убран** (15.09.2026). Причина: схемы, видео и вопросы дня лежат вне `docs/`, куда редактору писать запрещено. Пока выбор был, «Глава» вела к коммиту, который валит сборку — а сборка это и есть публикация, то есть падение блокировало выкладку всего сайта.

**Способов добавить и править — ровно три, пересечений нет:**

| Что | Куда | Кто |
| --- | --- | --- |
| правка текста страницы | `/edit`, либо «Предложить правку» (issue) под страницей | автор / любой |
| новая страница | `/edit` → «+ Новая страница» | автор |
| видео, ссылка, пресет в каталог | `/community` (issue) | любой |

Ссылка «Редактировать страницу» (`editUrl` Docusaurus) **убрана** — она вела в веб-редактор GitHub и была четвёртым путём, противоречащим обещанию «ни программы, ни git». Справочник для людей один: `docs/advanced/kak-dobavit-stranicu.mdx` («Как добавить материал»), на него ведут навбар, индекс раздела и экран «Нет доступа» в редакторе.

**Перенумеровать главы внутри трека безопасно** — числовой префикс в URL не попадает, а номер обложки читается из имени файла. Ничего править вручную не нужно. Переименовывать файлы **обратным порядком** (13→ сначала, потом 12), иначе `mv` попадёт в существующее имя.

**`chapterId` менять нельзя.** К нему привязаны прогресс, избранное, XP, словарь, вопросы дня и дашборд наставника — а не к пути. Переезд главы между треками дёшев, смена `chapterId` — нет.

## 6. Из чего состоит глава (канон v2+)

Обязательный минимум, его проверяют стражи:

- `<ChapterCover chapterId="…" />` сразу после фронтматтера;
- `<ChapterProgress chapterId="…" />` — знаменатели считает карта знаний, руками их не пишут;
- 2–5 `<Figure>`, ровно один `<ChapterExam>`, 4–5 видео;
- `<SectionAnchor>` в **конце** каждой секции (метка «секция прочитана» стоит после текста, не до);
- `<Hint type="tip" | "important" | "fact">` — **других значений нет**, невалидное падает только на `build`;
- `<Block kind="trainer" | "quiz" | "breakdown" | "vocab" | "cheatsheet" | "fact">`.

Содержательные требования калибровки Олега: посимвольный `SyntaxBreakdown` на каждую новую конструкцию, каждый символ объяснён при первом появлении, построчный разбор примеров, секция «Типичные ошибки» с **настоящими** текстами компилятора, `SelfCheck` после каждой крупной секции, объём не режется ради краткости, каждый пример исполняемый (`KotlinPlay`).

## 7. Инварианты, которые НЕ ловит ни один тест

Это самое ценное в файле. Всё остальное поймает CI.

**Каталог сообщества переезжает на сервер** (16.09.2026). **Ручной отметки «пройдено» больше нет нигде** (15.09.2026). Прогресс считается по делам: `src/lib/chapterFill.ts`, формула — `(секции + идеальные проверки + тренажёры) / (всего секций + проверок + тренажёров)`. Проверка с ошибкой НЕ засчитывается; тренажёр засчитывается фактом прохождения — общей шкалы «верно» у сорока шести механик нет. **Тренажёры вошли в счёт 17.09.2026**: до этого в шапке главы висело отдельное «Тренажёры 0/6», а сосуд наливался до крышки, ни одного не спросив. Ключ `pgk-progress` удалён; тема сосудов лежит в `prefs` того же store.

Кто это читает: сосуды Маршрута, карточка «Продолжить», сертификат и **тренажёр слов** — он берёт словарь из глав, наполненных до крышки. Менять формулу — значит двигать все четыре разом: при правке 17.09.2026 упали ровно `ContinueCard.test.tsx` и `WordsTrainer.test.tsx`, и это правильный список.

**`ChapterProgress` — арифметику больше не пишут руками, и это единственный инвариант отсюда, который удалось убить.** Знаменатели считает `knowledge-map.mjs` прямо по тексту главы: секции — по `<SectionAnchor>`, квизы — по `<SelfCheck>` **плюс один за `<ChapterExam>`** (экзамен пишет в тот же счётчик через `markQuizDone(chapterId, 'exam', …)`), тренажёры — по `trainerId=` (это НЕ то же, что блоки `kind="trainer"`: тренажёр без `trainerId` прогресс не пишет и в знаменатель не идёт — так в `linux-terminal`, где блоков семь, а тренажёров шесть).

Пока числа писали руками, компонент делал `Math.min` и молчал: завысил — полоса никогда не дойдёт до 100 %, занизил — лишние прохождения теряются. Так 41 глава из 52 оказалась с заниженным знаменателем (правило про экзамен было записано здесь неверно, исправлено 05.09.2026), а в `kotlin-null` заявили 4 квиза при трёх написанных. Пропсы `totalSections` / `totalQuizzes` / `totalTrainers` у компонента остались — они перекрывают расчёт, и нужны только если посчитанное по тексту заведомо врёт.

**Шкала уровней калибруется под объём платформы, а не наоборот** (18.09.2026). Прежняя кривая (показатель 1.75, десять званий) давала максимум на 844 XP, тогда как контента примерно на 18 000: «Чемпион» закрывался за шесть глав из 137, и 95 % программы не двигали ничего. Калибровали её при двадцати двух главах и с тех пор не трогали. Теперь показатель 2.6 и пятнадцать званий, максимум 17 137 XP. У всех, кто учился на старой кривой, уровень стал ниже — прогресс не потерян, пересчитана шкала. Страж в `levels.test.tsx` считает доступный XP прямо из данных и требует, чтобы максимум лежал между 60 % и 120 % от него: вырастет контент — тест напомнит. Тесты, которым нужен порог уровня, берут его через `xpForLevel(2)`, а не числом.

**Число XP печатает `store.addXp`, а не компонент** (18.09.2026). Множитель серии поднимает начисление до ×1.5, и карточка с константой расходилась с тостом: «+20 XP» против «+30 XP» за одно действие. `addXp` возвращает фактически начисленное, все 34 места показывают возврат, а страж `scripts/xp-display.test.mjs` не даёт константе вернуться. **Группы построены целиком и в бою не использовались** (проверено 21.09.2026: в боевой базе 0 групп, 0 участников, 1 пользователь — сам Олег). Путь пройден вручную на локальном сервере за наставника и двух студентов: `DEV_LOGIN=1 MENTORS=teacher SESSION_SECRET=… DB_PATH=/tmp/… PORT=4599 BASE_URL=http://localhost:4599 node server/index.mjs`, дальше `/api/auth/dev-login?login=X` отдаёт токен во фрагменте `Location`. Создание группы, код, вступление, `PUT /progress`, сводка с покрытием по главам — работает всё. Прогресс шлётся именно `PUT` и телом-снимком без обёртки; ученик удаляется `POST /mentor/groups/:id/remove`, а не DELETE. Единственная дыра, которая нашлась: `myGroups` был написан и ни разу не вызван, поэтому вступивший по коду терял след группы при перезагрузке — теперь группы едут в `/me`. Страж в `server/groups.test.mjs` не даёт остаться мёртвому запросу про группы.

**Одна вкладка больше не стирает другую** (21.09.2026). `persist()` пишет ВЕСЬ снимок из памяти, и пока вкладка не знала о чужих записях, она откатывала всё сделанное в соседней — молча. Теперь store перечитывает хранилище по событию `storage` и при возврате на вкладку (замороженная в bfcache событие пропускает). Слиянием это НЕ лечится: `mergeProgress` объединяет «по лучшему», а в store есть настоящие удаления — избранное и пресеты воскресали бы.

**Пространства имён CSS плоские, и корни разъезжаются молча** (21.09.2026). Стили лежат в трёх общих файлах, попадают в одну сборку и не изолированы ничем: два компонента с одинаковым коротким корнем (`gb`, `tc`, `st`, `cc`) красят друг друга. За один день это выстрелило трижды. Худший случай: плашка игрового слоя заняла `.gb`, которым уже звался корень Конструктора тренажёров, — её `white-space: nowrap` растянул `<section>` Конструктора на 1886 px, и **весь /gym поехал вбок на проде**. Ни typecheck, ни vitest (рендерит компонент в одиночку), ни сборка этого не видят. Теперь под стражем `scripts/css-roots.test.mjs`. Он смотрит ВСЕ классы в `className`, а не первый: в «gym-section gb» виновник стоял вторым, и первая версия стража его пропустила. Общие классы С ДЕФИСОМ (`ac-card`, `keys-kbd`, `sc-option`) — наоборот, норма и намеренно переиспользуются; страж их не трогает. Разрешённые пересечения корней перечислены в нём же списком `РАЗРЕШЕНО`.

**Таблица рекордов показывала не то, что обещала** (21.09.2026). Под заголовком «Тренажёры» шли только механики, записавшие скорость, — их четыре из сорока шести, поэтому две сотни пройденных упражнений выглядели как потерянный прогресс. Теперь строка на каждый пройденный тренажёр, скорость там, где она есть, прочерк там, где её не бывает. Экзаменов по блокам в рекордах не было вовсе: `ChapterExam` пишет и в `exams`, и в `quizLog`, а `BlockExam` — только в `exams` под ключом `block:<id>`, мимо всех читателей. Они идут первыми строками таблицы квизов: обрезка в 25 строк иначе прятала бы их за проверками. Обе таблицы обрезаны — у прилежного студента там 664 строки.

**Ширина текста в схемах и обложках.** SVG не переносит текст. Единственная надёжная проверка — настоящий `getBBox()` против `viewBox`. Оценка «на глаз по длине строки» врёт.

## 9. Правило фактуры: живой прогон, не по памяти

Каждый пример кода, каждое сообщение компилятора и каждый вывод программы в главе **сняты вживую в этой же сессии**. Не по памяти, не «примерно так».

- **Kotlin:** `POST https://api.kotlinlang.org/api/2.4.10/compiler/run?filename=File.kt`. JVM плейграунда — 17.0.20.
- **TypeScript:** локально `npx tsc --noEmit --strict …` (сейчас 6.0.3), запуск — `node file.ts` напрямую: Node 24.14.1 сам срезает типы.
- **Видео:** кандидатов набирать поиском YouTube (`user-agent: Mozilla/5.0`, регексом по `videoRenderer`), затем **обязательно** проверять каждый через oEmbed:
  `https://www.youtube.com/oembed?format=json&url=…` — не 200 значит мёртвое или приватное. Так отсеялось `AkL7uFm8ze4`, которое выглядело живым.
- Коды ошибок TS (`TS2322`, `TS18047`, …) и тексты Kotlin копируются из реального прогона.

## 11. Ловушки среды

- **Новый модуль сервера надо ещё и положить в образ.** `server/Dockerfile` раньше копировал файлы поимённо (`COPY index.mjs merge.mjs`). 16.09.2026 новый `linkcheck.mjs` доехал на сервер, но не попал в контейнер, и кабинет лёг целиком: 502 на всём, включая `/health`. Теперь `COPY *.mjs`. Если понадобится не-`.mjs` файл — проверить, что он в образе, а не только в `server/`.
- **«Docusaurus found broken anchors» на /gym — ложная тревога, но не вся.**
  Проверяльщик якорей знает только якоря заголовков и не видит `id`, который
  `<Block>` рендерит из `blockId`. Поэтому 31 ссылка Зала помечается битой,
  хотя все 144 ссылки с якорем реально резолвятся в собранном HTML (сверялось
  по `build/**/index.html` 17.09.2026). Гасить это `onBrokenAnchors: 'ignore'`
  нельзя — потеряется настоящая проверка ссылок на заголовки. ВАЖНО: когда
  предупреждений станет больше 31, это уже не шум. Так нашлись 84 настоящих
  битых ссылки: у блоков печати нет атрибута `blockId`, а генератор подставлял
  туда `trainerId` — `<Block>` без `blockId` не рендерит `id` вовсе. Теперь
  реестр в таком случае пишет `null`, ссылка ведёт на главу, и это под стражем.
- **HTML сборки минифицирован, атрибуты без кавычек.** В `build/**/index.html`
  лежит `id=trainer-bug-hunt`, а не `id="trainer-bug-hunt"`. Греп вида
  `id="[^"]*"` не находит НИЧЕГО и выглядит как «элемента нет». Искать
  `\bid=(?:"([^"]+)"|([A-Za-z0-9_:.-]+))`.
- **JS-прокрутка в панели браузера не работает.** `window.scrollTo` и
  `scrollIntoView` не двигают страницу (`scrollY` остаётся 0), хотя настоящее
  колесо через `computer {action:'scroll'}` двигает. Переход по якорю при этом
  проверяется присвоением `location.hash` — оно срабатывает.
- **Ленивые картинки в скрытой панели не грузятся никогда.** Панель не рисует кадры, пересечения с областью видимости не происходит, `loading="lazy"` не срабатывает. Проверять через `new Image()` или показав панель.
- **Сначала спроси, едет ли страница ВООБЩЕ.** `document.documentElement.scrollWidth > clientWidth` — единственный ответ на вопрос «есть ли горизонтальная прокрутка». Только если да, ищи виновника по правому краю. Иначе получишь гору ложных: на главе 17.09.2026 перебор по правому краю выдал 113 «переполнений» (таблицы, код, `sb-part`), а страница вбок не ехала вовсе — всё это живёт внутри своих прокручиваемых обёрток, и так задумано.
- **Переполнение страницы ищут по правому краю, а не по `scrollWidth`.** У элементов с `text-overflow: ellipsis` `scrollWidth` всегда больше бокса — это норма, а не переполнение. Виновника выдаёт `getBoundingClientRect().right > clientWidth`; так нашёлся `<select>` фильтра, растянутый под самое длинное название главы.
- **cwd сбрасывается между вызовами Bash.** Каждая команда начинается с `cd …/platform &&`. Ловилось многократно.
- **zsh калечит кириллицу в подстановке команд.** Разбор JSON — внутри `node --input-type=module`, не в шелле.
- **Скрытая панель не проигрывает переходы.** Если панель не показана, страница не рисует кадры: CSS-`transition` не двигается, и `getComputedStyle` НАВСЕГДА отдаёт стартовое значение. Выпадающее меню с `opacity 0 → 1` выглядит сломанным, хотя каскад верный. Проверять так: `el.style.transition='none'` + перевесить класс + мерить. Съело полчаса 15.09.2026.
- **После смены темы ждать, пока доиграет `transition`.** Если у измеряемого свойства есть переход (у `.cp-cell` это `background 0.15s`), `getComputedStyle` сразу после флипа `data-theme` отдаёт ПРОМЕЖУТОЧНЫЙ кадр. Дважды 17.09.2026 это выглядело как «в светлой теме цвет остался тёмным»: читалось `rgb(91,103,130)`, а через 2.5 с — честные `#d8dfec`. Мерить после выдержки или с `transition:'none'`.
- **`getComputedStyle` возвращает ЖИВОЙ объект.** Сохранить его и прочитать поля позже — значит прочитать состояние на момент чтения, а не на момент съёмки. Снимать значения сразу в обычный объект.
- **Панель браузера бывает скрыта:** скриншоты выходят пустыми, а `window.innerWidth` крошечный, поэтому `scrollWidth > innerWidth` даёт ложное «переполнение». Перед любым замером — `resize_window` (1280 и 375), проверять через `javascript_tool` / `read_page`.
- **Замер всех глав разом:** одним `javascript_tool` — `fetch` каждой страницы, `DOMParser`, вставка SVG в скрытый `position:absolute;left:-9999px;width:900px` div, потом настоящий `getBBox()`. Ходить по каждой главе не нужно.
- **Откуда брать собранные страницы для замера:** `preview_start {name:"edu-build"}` — статический сервер на 8795 поверх `build/`, конфигурация лежит в `~/Documents/claude/.claude/launch.json` (не в репозитории). Дальше один `javascript_tool` с `fetch` + `DOMParser` + `getBBox`.
- **Субагенты делят браузер с основной сессией** — их замеры уезжают на чужую страницу. Субагентам запрещено: dev-серверы, сборки, тесты, коммиты.
- Дев-сервер поднимать только через Browser pane (`preview_start`), не через Bash.
